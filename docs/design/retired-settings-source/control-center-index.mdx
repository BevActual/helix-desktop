Control Center is two surfaces. **Home** is the quick menu: sound, brightness, network, Bluetooth, night light, Do Not Disturb, and media, with no sidebar. **Settings** is the sidebar window: Appearance, Desktop, Device, Services, and the rest. Open Home from the control-center bar widget or by right-clicking empty space on a bar. Open Settings with IPC and no tab name:

```sh
noctalia msg panel-toggle control-center
noctalia msg panel-toggle control-center home
```

Pass a context to jump straight to a Settings page:

```sh
noctalia msg panel-toggle control-center audio
noctalia msg panel-open control-center system
noctalia msg panel-toggle control-center author/plugin:displays
```

## Sidebar

Set `sidebar` under `[control_center]` for tab navigation in the **Settings** window (`noctalia msg panel-toggle control-center` with no tab name, or the gear on Home).
Use `"full"` for icons and labels, `"compact"` for icon-only tabs, or `"none"` to hide the sidebar. Home is always a menu and does not use this setting.
The full sidebar carries the pages-and-settings search field; in compact mode a search glyph at the top of the rail (or `/` / Ctrl+F) reveals the field under the tab header, and it folds away again when it loses focus with nothing typed.

Set `sidebar_section` for opens that jump straight to a tab (volume, network, and media bar widgets, or `noctalia msg panel-toggle control-center audio`).

Keyboard navigation uses the global [`[keybinds]`](/noctalia/configuration/shell/#keybinds) actions: `tab_next` / `tab_previous` switch between the sidebar and the active tab body; arrow keys move within the focused pane.

```toml
[control_center]
sidebar = "compact"
# sidebar_section = "compact"  # optional; defaults to the same as sidebar
# width = 700  # full-sidebar width in pixels (600–1600)
# height = 700 # window height in pixels (480–1200)
# show_session_button = true   # Power tab button in the Home header
# hidden_tabs = ["monitor", "weather"]  # hide tabs you never use
```

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `sidebar` | string | `"compact"` | Sidebar in the Settings window: `"full"`, `"compact"`, or `"none"` |
| `sidebar_section` | string | `"compact"` | Sidebar when opening straight to a tab: `"full"`, `"compact"`, or `"none"` |
| `width` | int | `700` | Control Center width in pixels (`600`–`1600`). This is the full-sidebar width; the compact and no-sidebar modes scale down from it. Size it like a Settings window when you want leftover catalogs to spread out. |
| `height` | int | `700` | Control Center height in pixels (`480`–`1200`). Leftover catalogs, grids, and specimens fill the extra space. |
| `show_session_button` | bool | `true` | Show lock, suspend, log out, restart, and shut down on Home. |
| `hidden_tabs` | array | `[]` | Tab [context IDs](#sidebar-tabs) to hide from Settings. Empty shows every available tab. Editable from **Settings → Control Center**. Home is the quick menu and is not a sidebar tab. |

The sidebar follows macOS System Settings: unlabeled clusters separated by dividers, in this order:

1. Network, Bluetooth, Tailscale, Phone
2. Notifications, Sound, Screen Time
3. Theme, Control Center, Launcher, Privacy & Security, System, Packages, Clock
4. Desktop & Dock, Displays, Wallpaper, Power
5. Keybinds, Shell, Printers, Camera
6. LocalSend, Syncthing, Cast
7. Apps: Calendar, Weather, Media, Capture, Clipboard, AI, Templates, plugin tabs, and Plugins
8. Hooks, and Niri or Umbriel on those compositors

Some tabs hold related pages as sub-tabs, shown as chips under the tab title. **Privacy & Security** holds Privacy, Firewall, and Security. Their ids (`privacy`, `firewall`, `security`) still open that sub-tab directly. User `hidden_tabs` hide any sidebar tab; sub-tabs can't be hidden individually yet.

Enabled plugins that declare a `[[control_center_tab]]` are the same kind of sidebar entry as the built-in pages:
they appear in the Apps cluster, just before Plugins, each with an id. Built-in ids stay short (`monitor`, `audio`); plugin tabs use the full entry id
(`author/plugin:entry`). Hide any of them except Home via `hidden_tabs` or **Control Center → Control Center**.
See [Control Center tabs](/noctalia/plugins/development/manifest/#control-center-tabs).

Any tab except Home can also be hidden manually with [`hidden_tabs`](#sidebar) (use the context ID, e.g. `"monitor"`). Hidden tabs drop from both the sidebar and keyboard navigation.
Every available tab except Home that isn't hidden also gets its own row in the launcher's [Panels provider](/noctalia/launcher/#panels) (`/pan`), so you can jump straight to, say, Bluetooth without landing on Home first. Home remains available through the main Control Center row.

## Design language

Helix follows Apple Human Interface Guidelines as a hierarchy, not a skin. Liquid Glass is chrome. Leftover is content.

| Layer | Surfaces | Helix mapping |
|-------|----------|---------------|
| Chrome | Panel, sidebar, header | `[shell.panel].glass` 0–1 (solid → clear) plus `[shell.panel].refraction`. Clear needs a dimming layer so type stays readable. Do not nest glass-on-glass. helix-niri writes `liquid-glass`; stock niri maps refraction to chrome blur. |
| Leftover | Compact cards, leftover catalogs, grouped lists | Solid wells (`applySectionCardStyle`, `applyContentCardStyle`). Color and type live here. |
| Modules | Power session plate, Home sound and brightness | Frosted functional plates (`applyModuleWellStyle`), not a second glass layer. |
| Widgets | Home media, desktop widgets | Glanceable. Deep-link into Media. Not mini Control Center pages. |

**High Contrast** on Effects maps to Increased Contrast and Reduced Transparency: palette stretch, opaque chrome and leftover, contrasting outlines, and no module softness. **Motion** maps to Reduced Motion. Concentric rounding uses `radius3xl` on leftover wells and `radius2xl` on grouped lists inside them.

Every tab has one glass compact card. The panel header carries the tab title, so the compact card does not repeat it. Leftover wells, schema settings groups, and gear editors label their group with one bold body-size header (`addTitle` / `makeCardHeaderRow`); the larger title size is reserved for values such as battery percent, local time, or the track name.

Catalog tabs follow Wallpaper: icon sources, search, and the current pick on the compact card; leftover is only the grid. Theme organizes appearance sources the same way Capture organizes Screenshot and Record. Leftover catalogs and editors sit in leftover wells (`applyContentCardStyle`), not a second glass card. Size Control Center like a Settings window (`width` / `height` under `[control_center]`) so leftover catalogs can use extra columns. Live previews stay only where leftover does not already show the choice, and the running shell is not already the preview.

## Home

Home is the quick Control Center. The control-center bar widget and a right-click on empty bar space open it at menu size, without a sidebar. `noctalia msg panel-toggle control-center home` does the same. The window hugs the modules. The panel chrome stays Liquid Glass. Sound and brightness have visible labels in a module well. Wi-Fi, Bluetooth, Night Light, and Do Not Disturb show a stable name and a secondary status line; Tailscale appears when available. Click the glyph to toggle the feature. Wi-Fi, Bluetooth, and Tailscale detail buttons open their native Settings pages and close Control Center; if Settings is unavailable, they open the existing detail tab. Night Light and Do Not Disturb keep their shell detail tabs. Capture and Phone are visible actions that open their existing shell surfaces. Labeled Lock, Suspend, and Power actions sit in a session well. **Power** opens the full session controls, including log out, restart, and shut down.

While something is playing, Now Playing sits under the toggles and the menu grows to fit it. Click the card to open **Media**. When nothing is playing the card hides.

Pins you add show as a grouped list under the session well. The header gear opens Settings on the Control Center page (pins, sidebar, size). `noctalia msg panel-toggle control-center` with no tab opens Settings on Theme. `noctalia msg settings-toggle` with no section still opens Theme.

The pin list is configured on that Control Center settings page; see [Control Center shortcuts](/noctalia/control-center/shortcuts/).

Set `show_session_button = false` under `[control_center]` to hide the session well. This does not affect Home pins configured with `type = "session"` or session widgets on the bar. Custom session actions stay on the session panel behind Power's gear.

## Theme

Theme is the Appearance hub. Compact sources are Palettes, Chrome, Icons, Type, Effects, and Language, the same pattern Capture uses for Screenshot and Record. Chrome leftover is Glass, Scale, and Roundness editors, like Effects leftover for Borders, Shadows, and Speed. Wallpaper and Templates stay sibling Appearance catalogs.

Palettes leftover matches Wallpaper: Built-in, Wallpaper, Community, and Custom sources, Dark/Light/Auto, search, save, and the current palette sit on the same compact card as the domain switch; leftover is a uniform swatch grid. Auto shows the next day/night switch under the toolbar; tap that caption to open Weather for location. The compact card’s Color row is equal tappable role swatches. Tap a swatch to customize that role for the current light or dark mode; the shell saves a custom palette and switches to it.

On Wallpaper palettes, a photo button opens the Wallpaper tab. Save-as-custom sits with the sources. Header gear follows the active source: palettes open shell mode, Pure Black, and on niri window decorations and compositor blur.

`noctalia msg panel-toggle control-center theme` opens Theme. `appearance` is an alias. `glass`, `icons`, `type`, `scale`, `roundness`, `effects`, and `language` open the matching source. `chrome` opens the Chrome source.

### Glass {#glass}

Glass is a Chrome leftover editor for panel chrome: a Solid→Glass slider for fill and dimming, and a Refraction toggle. The running shell is the preview. Clear adds a dimming layer so leftover type stays readable. Compact cards and catalogs stay leftover, not nested glass-on-glass. On helix-niri, Refraction writes `liquid-glass` into `noctalia-blur.kdl` with strength from the slider; on stock niri it is chrome blur only. High Contrast frosts chrome and turns refraction off.

`noctalia msg panel-toggle control-center glass` opens this source.

### Icons {#icons}

Icons sets application icon style. Default and Tinted are compact sources, with a current preview on the right. Leftover is the tint catalog when Tinted is on: palette roles or a custom color for dock, tray, taskbar, and launcher icons. Picking a tint turns Tinted on.

`noctalia msg panel-toggle control-center icons` opens this source.

### Type {#type}

Type is the live page for the shell font. Search and the current family sit on the compact card. Leftover is the font grid; each tile shows Aa in that family. The first tile is System default (empty `shell.font_family`).

`noctalia msg panel-toggle control-center type` opens this source.

### Scale {#scale}

Scale is a Chrome leftover editor for interface scale. The leftover card is the slider and caption. The running shell is the preview.

`noctalia msg panel-toggle control-center scale` opens this source.

### Roundness {#roundness}

Roundness is a Chrome leftover editor for corner radius. Shell, Bar, Dock, and (on niri) Windows sources share one slider. The running shell is the preview.

`noctalia msg panel-toggle control-center roundness` opens this source.

### Language {#language}

Language sets the shell UI language. Search and the current locale sit on the compact card. Leftover is Auto plus supported translations. Auto follows the system locale; untranslated strings fall back to English.

`noctalia msg panel-toggle control-center language` opens this source. `noctalia msg settings-toggle language` opens the same page.

### Effects {#effects}

Effects is the live page for contrast, motion, borders, and shadows. High Contrast and Motion are compact icon toggles. High Contrast frosts chrome and leftover wells and draws contrasting outlines. Borders, Shadows, and Speed sources swap leftover controls. Animation speed hides when Motion is off. Shadow direction and opacity hide when popup shadows are off. Panel glass lives on Glass; icon tint lives on Icons.

`noctalia msg panel-toggle control-center effects` opens this source.

## Wallpaper

The Wallpaper tab is the same picker used by the dedicated wallpaper panel: a thumbnail grid from your configured folders, Wallhaven search, a Video source, a Daily Bing/NASA source, and a folder button to choose any image. Library, Wallhaven, Video, and Daily share one compact card. Icon sources, search, and that source's tools sit on the left; the current wallpaper, Display, star, and lock-screen sit on the right. The grid sits under the card. Flatten, sort, color, and Wallhaven filters open from the Filters control. Theme-from-wallpaper controls appear in the same card when that wallpaper is starred. Empty, error, and download status use a caption in the card. Video runs `mpvpaper` directly; `mpvpaper` must be installed.

Header gear opens wallpaper settings: fill mode, directories, per-monitor folders, automation, the Wallhaven API key, Daily source, and on niri the overview wallpaper preset (none, blurred backdrop, stationary, or a flat color) plus backdrop blur/tint. `noctalia msg settings-toggle wallpaper` opens that settings view. The floating wallpaper panel remains available from the bar widget and `noctalia msg panel-toggle wallpaper`. `noctalia msg panel-toggle wallpaper daily` (or `bing` / `nasa`) opens Daily on that panel; `noctalia msg panel-toggle control-center wallpaper daily` does the same in Control Center.

## Templates

The Templates tab browses app-theme templates the same way Wallpaper browses images. Icon sources, Enable, and catalog status share one compact card; the grid sits under it. Hover Built-In, Community, and User. Built-In and Community keep Enable on the right of that card; User hides it. Search, Filters, and sort sit with the grid. Enabling a template applies it on each theme change. Header **Apply** rerenders every enabled template for the current palette (`noctalia msg templates-apply`).

The header **+** button picks an installed application. If a built-in or community template matches that app, Helix enables it. Otherwise it scaffolds a user template under `~/.config/noctalia/templates/` and opens the starter file so you can map tokens to the app's theme format. A sheet then asks for the output path the application actually reads, plus an optional post-hook. On the User catalog, each tile's gear edits those fields or deletes the GUI-created entry (starter files stay on disk). The header folder button opens that templates directory.

When Helix Greeter is installed, header gear has **Sync Now** and **Auto-Sync** to copy wallpaper, colors, and monitors to the login screen. Built-in catalogs also offer a GTK Templates row when GTK templates are off.

Palettes stay on **Theme**.

Header gear opens greeter sync when it is available. `noctalia msg settings-toggle templates` opens that settings view. Community catalog search from a settings search still offers **Browse Templates** as a sheet.

## Keybinds

The Keybinds tab is niri compositor shortcuts. Click **Attention**, **Open**, **Apps**, **Capture**, **Sound**, and **Session** chips to switch leftover groups. Unfinished rows (missing, or a recommended key taken in your own `binds { }`) live on **Attention** and also remain in their category; that chip hides when the inbox is empty. Search shows matches from every section. ## Network

The Network tab uses the configured network backend to show wireless state and connection details. It is the destination for Wi-Fi shortcuts and network-related right-click actions.

The current connection line lists the IPv4 address, signal strength, radio band, and external IP. The band (`2.4 GHz`, `5 GHz`, `6 GHz`, or `60 GHz`) is shown only when the backend reports the connection frequency: NetworkManager and wpa_supplicant do, iwd does not.

The current connection card also shows live throughput (when the system monitor is running), the nameservers from `/etc/resolv.conf`, and a trailing DNS dropdown for the active NetworkManager connection: **Automatic** (DHCP), **Google**, **Cloudflare**, **NextDNS**, or **Custom**. Changing DNS updates the connection profile and reapplies it; Helix does not write `/etc/resolv.conf`. iwd and wpa_supplicant backends cannot set DNS from here.

**Connection Details** shows addresses, live throughput, and DNS settings, with labeled tools to ping, copy the LAN IPv4 address, run a short download speed test, or share the current Wi-Fi network as a QR code and join string. Use Back or Escape to return to the network list. Sharing copies a `WIFI:` payload with the SSID. On NetworkManager, the stored PSK is included when GetSecrets can return it; otherwise the QR still starts the join flow and the other device asks for the password. 802.1X networks never embed a password.

Click Wi-Fi, VPN, and cellular chips on that card to swap which list keeps leftover height. The VPN and cellular chips appear when those connections exist.

**Wi-Fi Settings** opens the Wi-Fi band filter and ignored SSIDs. Dual-band networks are listed once (the strongest BSS), so a 5 GHz filter hides a network whose strongest copy is on 2.4 GHz. iwd access points have no frequency and stay visible only when the band filter is **All**.

`[control_center.network]` holds those Network tab options:

```toml
hidden_ssids = []
nextdns_id = ""
custom_dns = ""
```

### Enterprise Wi-Fi (802.1X)

Clicking a WPA2/WPA3-Enterprise network opens a credential form instead of the pre-shared-key field: EAP method (PEAP or TTLS), inner authentication, identity, anonymous identity, server domain suffix, and CA certificate path. The password field below the form is the one used for the EAP login.

PEAP accepts MSCHAPv2 only, so the inner dropdown is pinned and disabled while PEAP is selected; TTLS also allows PAP, MSCHAP, and CHAP. Leaving the CA certificate path empty trusts the system CA store; a path must be absolute and pins that file instead of the system store. The server domain suffix is the RADIUS server name suffix your organization publishes, and is optional.

Enterprise networks are recognized on the NetworkManager backend only; the wpa_supplicant and iwd backends still show the pre-shared-key prompt for them, which an 802.1X network cannot accept. Certificate-based EAP-TLS, including WPA3-Enterprise 192-bit, is not supported: the form says so instead of writing a profile NetworkManager would reject. Use `nmcli` or another NetworkManager front end for those networks.

### Cellular

When ModemManager reports a modem, the Network tab adds a **Cellular** card with a mobile-data switch and one row per modem showing its operator (or hardware name), state, access technology (`5G`, `LTE`, `HSPA+`, ...), and signal percentage. The card disappears again when ModemManager stops or the modem is unplugged.

The switch follows GNOME's mobile-data semantics: with a saved NetworkManager `gsm` profile it turns the data connection on and off and leaves the modem registered on the network; with no such profile it powers the modem radio itself. Turning it on can take several seconds while the modem enables, searches, and registers, and the switch holds the requested position until the change lands.

Cellular needs ModemManager running (`org.freedesktop.ModemManager1`) and, for mobile data, a `gsm` connection profile created with `nmcli` or another NetworkManager front end. Helix does not create or edit cellular profiles.

The Phone tab talks to the session KDE Connect daemon (`org.kde.kdeconnect`). Per-app casting is Android-only. Turning Ollama on loads the selected model. Clicking a model while the daemon is running loads it. Search on the compact card filters Installed by name, size class, or quantization. Rows show parameter size, quantization, and disk size from `GET /api/tags`; loaded VRAM comes from `GET /api/ps`. Compact and the leftover version line show total disk and memory in use. **Library** searches the Ollama catalog (the same search field, leftover is the result list). **Install** pulls a model (`POST /api/pull`); compact and the row show byte progress, and **Cancel** stops the download. **Retry** appears if a pull fails. A typed name that is not in the catalog is still offered so you can pull a tag such as `llama3.2:1b`. After a model is installed, **Select** pins it and switches to Installed. Installed rows can **Remove** a model (`DELETE /api/delete`) after a confirm tap. Compact **Start** brings the daemon up; **Load** appears when a picked model is not in memory. **Open** launches the Ollama desktop app when it is installed. The daemon toggle uses `systemctl --user start ollama`, then `ollama serve` if that unit is missing; stop uses the user unit (and a serve process Helix started). If Ollama is already running when Helix starts, the selected model is loaded. If nothing is selected and exactly one model is loaded, Helix remembers that one. A remote `ollama_host` lists models only and does not pull.

**Local** leftover also lists OpenAI-compatible CLI servers that answered `GET /v1/models` on loopback: llama.cpp (`:8080`) and vLLM (`:8000`). GUI apps (LM Studio, Jan) are omitted. Helix does not send chat completions.

**LocalAI** is the desktop's AI service layer: one OpenAI-compatible endpoint that serves chat, vision, tool calling, speech to text, text to speech, embeddings, image generation, and more from one process. It appears when a [LocalAI](https://localai.io/) server answers on `localai_host` (default `127.0.0.1:8080`, or `LOCALAI_ADDRESS`), when the `local-ai` CLI is on `PATH`, or when set to Always on. Helix tells LocalAI apart from a bare llama.cpp on the same port with `GET /v1/models/capabilities`, so that row is not double listed. Leftover has two compact sources. **Installed** lists every model with its capabilities (Chat, Vision, Tools, Thinking, Transcription, Speech, Embeddings, Image…), backend, context size, and whether it is resident (`GET /system`); the radio pins `localai_model`, the default that answers chat requests, and **Remove** deletes a model after a confirm tap (`POST /models/delete/NAME`). The **LocalAI** toggle starts or stops the server (`systemctl --user start local-ai`, then `local-ai run` if that unit is missing) when the CLI is installed; a Docker-hosted LocalAI is detected but not toggled. **Gallery** browses the LocalAI model gallery (`GET /models/available`, filtered on this machine by name, tag, or description). **Install** applies a gallery entry (`POST /models/apply`) and follows the job (`GET /models/jobs/UUID`) with byte progress on compact and the row; **Retry** appears if a job fails, and **Select** pins an installed entry. The first installed model becomes the default when nothing is pinned. **Open** launches the LocalAI web UI in the browser. A remote `localai_host` lists models only.

Desktop tools and plugins get the endpoint instead of each shipping their own runtime: `noctalia msg ai-usage-localai-endpoint [capability]` prints `url=… status=… model=…`, choosing the pinned model when it has that capability, otherwise the resident one, otherwise the first match (`chat`, `vision`, `tools`, `thinking`, `transcript`, `tts`, `embeddings`, `image`, `video`, `sound`, `vad`, `rerank`, `detection`). It exits non-zero when LocalAI is not running. Plugins read the same through `noctalia.aiUsage().localai`.

The desktop calls that endpoint for one-shot tools. Clipboard entries can **Summarize**, **Translate**, **Rewrite**, or **Read aloud**, and **Dictate** records the microphone until you tap it again, then copies the transcript. Recent screenshots can **Read** or **Describe** with a vision model; the result is copied to the clipboard. The same actions are `noctalia msg desktop-ai-summarize`, `desktop-ai-translate`, `desktop-ai-rewrite`, `desktop-ai-speak`, `desktop-ai-dictate`, `desktop-ai-read PATH`, and `desktop-ai-describe PATH`. Hermes stays the agent for anything that needs tools.

Tokens stay on this machine except for requests to that provider's own API. A failed refresh keeps the last good numbers. Open the tab with `noctalia msg panel-toggle control-center ai` (`ai-usage` is an alias), add a bar widget with `type = "ai"`, or add a Home shortcut with `type = "ai"` — the tile and bar widget show the hottest CLI quota (or the selected Ollama model / local inference status) and light up when a quota is near the warning threshold. Dump or refetch from scripts with `noctalia msg ai-usage-status` and `noctalia msg ai-usage-refresh`. Start, stop, pick, or install an Ollama model with `noctalia msg ai-usage-ollama-start`, `ai-usage-ollama-stop`, `ai-usage-ollama-model NAME`, and `ai-usage-ollama-pull NAME`; the LocalAI set is `ai-usage-localai-start`, `ai-usage-localai-stop`, `ai-usage-localai-model NAME`, `ai-usage-localai-install NAME`, `ai-usage-localai-delete NAME`, `ai-usage-localai-open`, and `ai-usage-localai-endpoint [CAPABILITY]`. Plugins can read the same snapshot with `noctalia.aiUsage()` instead of fetching tokens. The Control Center sidebar badge shows that same percent when it reaches **Usage Warning**. Header gear is `[control_center.ai_usage]`:

```toml
[control_center.ai_usage]
refresh_seconds = 120          # 30–900
claude = "auto"                # auto | on | off
cursor = "auto"
ollama = "auto"
localai = "auto"
warn_percent = 90              # 0 disables
warn_reset_minutes = 30        # 0 disables
# ollama_host = "127.0.0.1:11434"
# ollama_model = "llama3.2:latest"
# localai_host = "127.0.0.1:8080"
# localai_model = "qwen3-4b"
# gemini_daily_limit = 1000
# qwen_daily_limit = 2000
```

Helix notifies once when a quota crosses **Usage Warning**, and again when a busy quota (at least 50% used) will reset within **Reset Warning**. Each warning fires once per window until usage drops or the window resets.

## Settings

Settings pages are Control Center tabs. Theme hosts Palettes, Chrome, Icons, Type, Effects, and Language as compact sources. Chrome leftover catalogs Glass, Scale, and Roundness sit on the same compact card. Desktop & Dock hosts Widgets, Corners, Bar, Dock, Windows (niri), Panels, and OSD as compact sources, the same way Theme hosts Appearance. Nested leftover catalogs also sit on that compact card: Glanceable/Sound/Tools, Screen/Hot, Layout/Shape, Layout/Pinned, Spacing/Columns, Placement/Chrome, and Placement/Style. Widgets leftover is a catalog. The rest use leftover wells. `bar`, `dock`, `windows`, `panels`, and `osd` still open the matching Desktop source. Network, Bluetooth, Audio, Media, Monitor, Power, Notifications, Screen Time, Calendar, Weather, Camera, and System sit under **Device**. Privacy, Firewall, Security, Printers, Cast, and similar tools sit under **Services**. Launcher, keybinds, and shell sit under **Input**. Control Center options, niri, hooks, and plugins sit under **General**.

Domain options that belong with a live view are on that tab: theme and palette on Theme Palettes (Light, Dark, and Auto as tiles; Auto shows the next day/night switch; Built-in, Wallpaper, Community, and Custom palettes fill the leftover catalog), language on Language, font on Type, UI scale on Scale, corner radius on Roundness, panel glass on Glass, icon tint on Icons, high contrast and motion tiles plus leftover Borders/Shadows/Speed chips on Effects, greeter sync under Templates gear, the wallpaper picker on Wallpaper (header gear for folders, Wallhaven, and on niri overview wallpaper), location, units, and Weather enable under Weather gear (enable also on the compact-off card), night light on Monitor (force and temperatures when on), lock/suspend/logout/reboot/shutdown/caffeine on Power, world clock on Calendar, privacy captures plus approximate location and the startup ping on Privacy (header gear for capture-name filters), the enable toggle on Screen Time, Network DNS and Wi-Fi QR on Network, capture buttons on Capture, Dock Layout and Pinned leftover on Desktop, desktop Glanceable/Sound/Tools catalogs and Screen/Hot corner leftover on Desktop (header gear follows the active source), launcher pins and always-in-search providers on Launcher (header gear for appearance, placement, prefixes, auto-paste, and currency), Home shortcuts behind the Home header gear, and header gear on Notifications, Power, System, Calendar, Audio, Monitor, Media, Desktop, Bluetooth, Network, Capture, Screen Time, Theme, and AI for the longer forms.

Each settings page is searchable from the sidebar field above Home (or from the header when the sidebar is hidden). Press `/` or Ctrl+F to focus the field. An empty query keeps that page’s filter. A tab name (for example `calendar`) filters the sidebar and opens that live page; the same query is kept for that tab’s settings, so the header gear shows matching rows. Other queries search the settings registry on the current tab’s gear sheet when that section matches. If it does not, Control Center opens the best matching section in gear mode instead of always dumping onto Theme.

The plugin store, session/idle editors, notification filters, calendar accounts, community templates, and bar widget inspectors open as sheets in Control Center. The header Advanced toggle shows advanced settings. The ⋮ menu on a settings page exports config and saves a support report.

Open Theme with `noctalia msg panel-toggle control-center settings` or `noctalia msg settings-toggle`. Pass a section to land on that page, for example `noctalia msg settings-toggle bar` or `noctalia msg settings-toggle location` (Weather tab). `settings-toggle` without a section still lands on Theme. `appearance` is an alias for Theme.

The Niri page is shown only when the session is running under niri. Theme owns decorations and compositor blur; Desktop → Windows owns gaps, outer padding, and column width; Wallpaper owns overview presets and backdrop; Launcher owns type-to-launch.

## Power

The Power tab keeps live power state on compact cards and longer lists underneath, backed by UPower and `power-profiles-daemon`:

- **Session** - lock, suspend, logout, reboot, and shutdown as wrapping icon-and-text buttons. Reboot and shutdown use the destructive style. Custom session actions and countdown confirmation stay on the session panel behind header gear.
- **Battery** - charge percentage, charging/discharging state, time remaining (or time until full), current draw in watts, the power-profile segmented control (power-saver, balanced, performance), and caffeine (keep awake). Switching the profile here is equivalent to the Home shortcut and bar widget.
- **Battery charging** - charge-limit toggles and firmware/externally managed status when UPower exposes them
- **Battery Health** - current full-charge capacity as a percentage of the original design capacity
- **Connected Devices** - battery levels for peripherals such as Bluetooth mice, keyboards, and headsets

Charge limits, health, and connected devices sit in the leftover list and appear only when their data is available. The compact battery card requires a system battery, `power-profiles-daemon`, or an idle inhibitor. The tab itself is hidden on systems where neither UPower nor `power-profiles-daemon` is running.
