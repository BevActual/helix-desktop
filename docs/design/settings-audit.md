# Settings audit (2026-10-09)

Question asked of every Settings control: **does anything running in this session act on it?** The Tauri shell replaced the native
Helix shell, but Settings still listed the old shell's service settings. Checked by reading the consumers and, for theming, by changing
the setting on the live service and seeing which files changed.

| Page | Setting | Acted on by | Verdict |
|---|---|---|---|
| Appearance | `theme.mode` | helix-service theme pipeline: GTK, Qt, Warp, Brave themes, colour scheme | kept |
| Appearance | `theme.pure_black_dark` | same pipeline (generated files change when toggled) | kept |
| Accessibility | `accessibility.high_contrast` | helix-service sets the GTK high-contrast key | kept |
| Accessibility | `accessibility.ui_scale` | only the native shell | back, as the applications' interface scale (below) |
| Displays | `brightness.*` | the Tauri shell writes the backlight itself and ignores these | removed |
| Displays | `nightlight.*` | need a gamma provider; none exists in the Tauri shell (the live catalog has no rows) | removed |
| Sound | `audio.*` | feedback sounds and overdrive belonged to the native shell | page removed (output and input live in the control center) |
| Notifications | `notification.*` (12 rows) | the Tauri shell's own `org.freedesktop.Notifications` server reads none of them | replaced by a page of the two settings the shell honours (below) |
| Power & lock | `lockscreen.*`, `idle.*`, `battery.*` | helix-idle reads `~/.config/helix/idle.toml`, not these | replaced by a page that edits `idle.toml` |
| Dock | (all) | see settings-tauri.md | replaced earlier by `dock-settings.json` |

## What replaced them

* **Power & lock** edits `~/.config/helix/idle.toml` (lock after, screen off after, each can be switched off) through
  `helix_config::idle_prefs`; other keys in the file (the commands) are preserved, and helix-idle is restarted so it reads the file.
* **Displays** lists each connected output and sets its resolution (from the modes the monitor advertised), scale (100% to 200%), and orientation. With two or more displays it also sets arrangement and can turn an extra display off. Variable refresh appears only when the monitor supports it. The compositor applies the change immediately, and Settings records it in `~/.config/niri/helix-setup.kdl` (included from the compositor config). `tools/nested/settings-displays-test.sh`. **Night light** sits at the top of the page (switch, warmth in kelvin, an optional schedule with From and Until hours, a half-hour fade at each end). It writes `~/.config/helix/nightlight.json`, which the `helix-nightlight` service reads (see `compositor-integration.md`). On the Helix compositor Settings sends one request after each change and the compositor remembers the whole layout per set of connected displays (`compositor-integration.md`); no KDL is written. On another compositor Settings writes only the changed display to `helix-setup.kdl`, by its make-model-serial identity, and pins a resolution or position only when that was the thing changed. A "Remembered layout" row says whether this set is saved.
* **Wallpaper** sets one picture for every display, or a picture for one connected display. The choice is `~/.config/helix/wallpaper.toml`: `[wallpaper.default]` for every screen, `[wallpaper.monitors.<connector>]` for one screen. `helix-wallpaper` already paints from that file and reloads it. `tools/nested/settings-wallpaper-test.sh` checks the file; `wallpaper-test.sh` checks the pixels.
* **Notifications** edits `~/.config/helix/notification-settings.json` through `helix_config::notification_prefs`: Do not disturb, quiet hours (a from/until window on the 24-hour clock, including through midnight), how long a banner stays when
  the application gave no time (2 to 15 s), and how many show at once (1 to 3). The shell watches the file and applies these to
  `helix_shell_model::notifications` with no restart. Quiet hours are checked again when the hour changes. Urgent banners still show, and the Do not disturb switch stays independent. Quick Settings writes the same Do not disturb value, so the two switches stay together and it survives a restart. `tools/nested/settings-notifications-test.sh` and `notifications-prefs-test.sh`.
* **Interface scale** (Accessibility, 0.8 to 1.5) is followed by Settings, Software, System Monitor and Mobius: each watches the
  setting through `helix_desktop_api::Desktop::watch_ui_scale` and zooms its own windows. The shell's bar, dock and panels do not
  follow it yet. `tools/nested/ui-scale-test.sh`.
* **Appearance mode** (dark, light, automatic) is followed by Settings, Software, System Monitor and Mobius through
  `helix_desktop_api::Desktop::watch_theme_dark`: `auto` is resolved with the same day and night schedule the service uses and
  re-checked each minute. They set `data-theme` on the page, and again after each page load. `tools/nested/ui-theme-test.sh`.
* **Dock** and **Wallpaper** are described elsewhere.

## Still to build, with their owners

* ~~Night light~~ — **Done**: `services/helix-nightlight` (a `wlr-gamma-control` client), `core/helix-nightlight-model`, and the rows on Displays. The **Quick Settings** Night Light tile reads and writes the same file (`helix_nightlight_model::{load, set_enabled}`; it is no longer a setting of the desktop service), so the tile, the Settings page, the Act/agent command and the key binding agree. With a schedule it can **follow sunset and sunrise** (from the place set in Date & time; the service asks the desktop service once a minute and uses `helix-theme`'s schedule, warming over half an hour after dark and cooling over the last half hour before sunrise).
* ~~A Sound page of real controls~~ — **Done.** Output and input device, volume and mute, and a microphone test (`Test microphone` on the Sound page). The test calls `Audio1.StartInputMeter` for the microphone in use, shows `InputLevel` while it is on, renews the eight-second lease, and calls `StopInputMeter` on leaving the page. `apps/helix-settings/web/src/pages/SoundPage.tsx`, `tools/nested/settings-sound-test.sh`.
* Notifications: banner time, banner count, the Do not disturb switch and quiet hours are done. Still open: per-application rules (they need a consumer in `helix_shell_model::notifications` first).
* The shell's own chrome does not follow the interface scale: the bar and dock set layer-surface sizes and exclusive zones, so they need to follow the scale rather than be zoomed.

* **Date & time** (`apps/helix-settings/src-tauri/src/datetime.rs`, `settings-datetime-test.sh`): *Time*: the current date and time, the **time zone** (a filterable list of the zones timedated knows) and **Set the time automatically** (NTP), both through `systemd-timedated` over the system bus with `interactive` on, so the desktop's own polkit agent asks for the password and Settings never sees it; the **clock** (Automatic, 12-hour, 24-hour), kept in `~/.config/helix/clock-settings.json`, which the shell watches and applies to the bar and the control center. *Location*: latitude and longitude (typed or dragged) and "Use my own day and night times" with the two times on the half hour; these are the desktop service's `location.*` settings, used by the automatic theme and by night light. Typed coordinates send nothing anywhere. **Find where I am automatically** (off by default) turns on `location.auto_locate`: the desktop service (`services/helix-desktop/src/location.rs`) asks **GeoClue** at city accuracy for this program (`org.helix.Desktop`), keeps the answer rounded to about a kilometre in `location.latitude`, `location.longitude` and `location.address`, and writes what happened (located, denied, unavailable) to `$XDG_STATE_HOME/helix/location-status.json` for the page. GeoClue decides where the answer comes from, and that can be a network lookup, so the switch says so. GeoClue refuses programs it has not been told to trust: the package installs `/etc/geoclue/conf.d/90-helix.conf` (`packaging/90-helix-geoclue.conf`); on a development machine copy it there and restart GeoClue. `tools/nested/helix-desktop-location-smoke.sh` runs the whole flow against a scripted GeoClue. Not done: setting the time by hand, and a date format.

* **Mouse & touchpad**, and **Typing** at the top of Keyboard (`apps/helix-settings/src-tauri/src/input.rs`, `settings-pointer-test.sh`): touchpad (tap to click, natural scrolling, pointer speed, ignore while typing, clicking by fingers or areas), mouse (natural scrolling, pointer speed, adaptive or flat acceleration, primary button on the right), the keyboard layout (a filterable list read from the system's xkb `evdev.lst`) and the key repeat delay and rate. These are **overrides held by the Helix compositor** (`compositor/src/helix/input.rs`, IPC `HelixInput` and `HelixSetInput`): the page shows what is in effect, a change takes effect at once, is remembered in `$XDG_STATE_HOME/helix/input-overrides.json`, and is applied over `config.kdl` every time the configuration is loaded, so the person's file is never rewritten and a setting never changed here stays as the file says. Another compositor reports nothing and the page says it needs the Helix one. Not done: several layouts at once, per-device settings, scroll speed, and gestures.
* **Default apps** (`apps/helix-settings/src-tauri/src/defaults.rs`, `settings-defaults-test.sh`): web browser, email, files and folders, text editor, pictures, PDF documents, video and music. The answer is kept where every desktop keeps it, `~/.config/mimeapps.list` (`[Default Applications]`), so any program that asks the system is told the same, and a choice made with another tool shows here. Programs on offer are those the system's `mimeinfo.cache` says open the kind's first type (a hidden or missing `.desktop` file is left out); a choice is written for every type of the kind that program opens, first in its list with the older entries kept after it, and the rest of the file (comments, other sections) is untouched. A kind nothing here opens has no row. Not done: a terminal (there is no standard setting for it), and per-type choices.
* **Accent colour** (Appearance; `settings-accent-test.sh`): eight named accents (blue, purple, pink, red, orange, yellow, green, graphite). The choice is the desktop service's `theme.accent` (a Helix setting, validated against `helix_config::settings::ACCENTS`). Every Helix application and the shell follow it: `helix_desktop_api::Desktop::watch_theme` reports the dark or light look *and* the accent, the app puts `data-theme` and `data-accent` on the page's root element (`helix_desktop_api::theme_script`, which only ever writes a plain lowercase name), and `core/shared-ui/style.css` turns the name into `--accent` and `--on-accent` for dark and light. The shell reads it from the quick-settings view. GTK 4 and libadwaita applications follow it too: the desktop service (`services/helix-desktop/src/accent_sync.rs`) mirrors the accent into `org.gnome.desktop.interface accent-color` (graphite becomes GNOME's slate), and does nothing where `gsettings` or the key is missing. Not done: Qt and GTK 3 applications (the theme pipeline would need to put the accent into its generated files). The compositor's focus ring follows it (see Windows and cursor).
* **Windows and cursor** (Appearance; `apps/helix-settings/src-tauri/src/look.rs`, `settings-look-test.sh`): animations on or off, the space between windows (0 to 64 px) and the cursor size (16 to 64 px), plus the colour of the focus ring, which is set whenever an accent is chosen (the accent's dark-theme colour; the ring and window borders are both recoloured and a gradient in `config.kdl` is replaced). These are **overrides held by the Helix compositor** exactly like the input settings (`compositor/src/helix/look.rs`, IPC `HelixLook` and `HelixSetLook`, `$XDG_STATE_HOME/helix/look-overrides.json`, capability `look_settings`): a change takes effect at once (layout config, clock, cursor theme reload and texture cache), is remembered, and is applied over `config.kdl` at start and on every reload. Another compositor reports nothing and the rows are not drawn. Not done: corner radius, shadows, and a separate ring colour from the accent.
* **Display arrangement** (Displays; `apps/helix-settings/web/src/pages/DisplaysPage.tsx`, `settings-arrange-test.sh`): with more than one display in use, a picture at the top of the page draws each as a box to scale; dragging one moves it. The drop is snapped by `compositor_ipc::snap_position` against the nearest edge of another display (never overlapping, never a gap, always facing a neighbour by at least a little, and level with the neighbour's edge when within 32 px), applied through the compositor's `Position` output action and remembered like any other display change. Because a display with no position of its own is placed by the compositor after the others, moving one first gives every other display the place it has now. The older "Arrangement" row per display (beside, above, below) stays for keyboard use. Headless test setups can ask for more displays with `HELIX_NESTED_EXTRA_OUTPUTS=1024x768,…`. The boxes are focusable and the arrow keys move the focused one (it is thrown a width and a half that way and snapped). Not done: identifying a display by flashing its number on the screen, and a primary display.
* **Top bar** (`apps/helix-settings/src-tauri/src/topbar.rs`, `core/helix-config/src/bar_prefs.rs`, `shell/helix-shell-tauri/src-tauri/src/bar_prefs.rs`; `settings-topbar-test.sh`, `shell-bar-prefs-test.sh`): a switch for each part of the bar that can go: the Apps button, the Mobius button, the workspace dots, the date beside the time, seconds in the time, and the Wi-Fi, Bluetooth, sound and battery icons and the battery percentage. The choices are `~/.config/helix/bar-settings.json` (only choices the person made are written; anything else keeps its default), which the shell watches once a second like `clock-settings.json`; the page puts `bar-hide-<item>` classes on the root element and `core/shared-ui/style.css` hides them. The control center and notification buttons are deliberately not on the list, so the bar can never be left without a way to reach them. Seconds make the bar's clock tick every second (the control center's stays on the minute). Not done: bar height and where it sits, ordering the items, an auto-hiding bar, and the dock-style presentation per display.
* **Power mode** (top of Power & lock; `apps/helix-settings/src-tauri/src/powerprofile.rs`): Power saver, Balanced or Performance, from power-profiles-daemon on the system bus (`org.freedesktop.UPower.PowerProfiles`, or the older `net.hadess.PowerProfiles`); only the profiles the daemon offers are shown, and no row at all when there is nothing to choose between. Reading and changing it needs no password on a normal desktop. The daemon is real-system only, so it has no nested test: `cargo test -p helix-settings powerprofile -- --ignored` checks reading and writing against the running daemon. Not done: the lid and power-button actions, suspend, and a battery-saver trigger.
* **Startup apps** (`apps/helix-settings/src-tauri/src/startup.rs`, `settings-startup-test.sh`): what starts when the person logs in, from `~/.config/autostart` and the system's `/etc/xdg/autostart` (Helix's session is a systemd one, so `systemd-xdg-autostart-generator` runs them and honours `Hidden=true`). A switch for each. Only the person's own folder is ever written: turning a system program off writes a file of the same name there with `Hidden=true` and turning it back on removes that file (so the system's entry applies again); a program the person added is turned off in place by the same `Hidden=true`, still whole. "Add a program" lists the installed applications (not already listed) in a filterable list and copies the chosen desktop file. A choice row with nothing chosen is drawn as that list with "Choose…", not as unselected buttons (`core/shared-ui/react/Rows.tsx`). Not done: removing a program the person added, adding a command that is not an installed application, and a delay.
* **Multitasking** (`apps/helix-settings/src-tauri/src/look.rs`, `settings-multitask-test.sh`): focus follows the pointer, when the focused column is centred (never, always, when needed), the hot corner that opens the overview, and whether choosing the workspace you are on goes back to the previous one. They are more of the compositor's look overrides (`HelixLook`/`HelixSetLook`, `look-overrides.json`), on their own page, applied at once and again on every reload. Not done: the default column width, workspace names and number, per-display workspaces, and the other hot corners.
* **Layout at large interface sizes** (shared `core/shared-ui/style.css`, `Rows.tsx`): with the interface scale at its largest the content column is only a little over 300 px, so a row now wraps its control beneath its text when they do not fit (stacked rows are exempt), and the sidebar is `clamp(190px, 30vw, 240px)`. A filterable choice list opens upward when there is no room below its button (a row at the bottom of the page was clipped, which made the Date & time test fail). The fake desktop can start with a scale (`HELIX_FAKE_UI_SCALE=2`) and the settings window's minimum width is 800, so a narrow window is only reached through the scale.
* **Settings sidebar scrolls** (`core/shared-ui/style.css`): with eighteen pages the list was taller than the window, so Privacy & agents and About could not be reached (the `settings` nested test caught it). The list now scrolls inside the sidebar, with no visible scrollbar, and its rows are a little tighter.
