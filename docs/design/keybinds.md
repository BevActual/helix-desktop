# Keybinds

The compositor and the shell are one project, so a shortcut is one thing: a chord, the thing it does, and who put it there. Today it is three:
a hand-edited `config.kdl` (niri's defaults plus ours, about 150 binds), a read-only viewer that parses those files, and the shell's own chords
(validate, cancel, arrows, copy) in the desktop service. This is the plan to make it one.

## Direction

1. **Shell actions are compositor actions.** `helix-shell "launcher"` (like `helix-summon`) asks the shell by name. The compositor makes the
   session-bus call itself (`org.helix.Shell1`: `TogglePanel`, `ToggleDoNotDisturb`, `AdjustVolume`, …) on its own thread, so a key press starts no
   script and no process. If there is no shell on the bus (or it does not take that name) the same request goes to `helix-panel <name>`, which
   knows every shell and is what binds used before. A name must be a short word (`[a-z0-9-]`, 32 characters); nothing else is passed on.
   `HelixCapabilities.shell_action` says whether the build has it, so nothing writes the new form for an older compositor.
2. **The compositor reports every bind** (`HelixBinds`: chord, action, title, source = niri default / the person's config / Helix, and whether
   another bind has the same chord), so Settings stops parsing KDL.
3. **Overrides, not rewrites.** Changes from Settings live in `$XDG_STATE_HOME/helix/bind-overrides.json`, are laid over `config.kdl` at start and
   on every reload, and take effect at once over IPC (`HelixSetBinds`), exactly as look and input do. `config.kdl` is never rewritten. An override
   wins over a bind the person wrote by hand on the same chord, and its row says so; removing it restores what was there.
4. **One page.** Window and shell shortcuts from the compositor, and the shell's in-app chords from the service, are listed together by what they
   do, with a key recorder that shows what it would replace. Keys the shell cannot live without (lock, summon, the Mod key itself) are refused.
5. **Registration.** Apps and agents ask for a shortcut by name; the person approves it in Settings. Nobody edits KDL.
6. **Clean up.** Drop the stale "Generated by Helix" header in `noctalia-binds.kdl` and the `noctalia msg` binds.

## Status

* Step 1 done: the `helix-shell` action, its capability flag, `tools/nested/helix-shell-action-test.sh`. Existing binds are *not* rewritten yet:
  an older compositor refuses a config with an action it does not know, so binds move to it only once the new compositor has been running.
* Steps 2 to 6 not started.
