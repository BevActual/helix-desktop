The Control Center is Helix's hybrid of a Control Center and Settings. **Home** is the live Control Center: glass modules, status, and shortcuts. Every other sidebar page is a Settings-style live tab (state and primary actions on the page, policy in the header gear). Open it from the control-center bar widget, by right-clicking empty space on a bar, or with IPC:

```sh
noctalia msg panel-toggle control-center
```

Pass a context to jump straight to a tab:

```sh
noctalia msg panel-toggle control-center audio
noctalia msg panel-open control-center system
noctalia msg panel-toggle control-center author/plugin:displays
```

## Sidebar

Set `sidebar` under `[control_center]` for tab navigation when Control Center opens on **Home** (control center widget, bar background click, or `noctalia msg panel-toggle control-center` with no tab name).
Use `"full"` for icons and labels, `"compact"` for icon-only tabs, or `"none"` to hide the sidebar.

Set `sidebar_section` for opens that jump straight to a tab (volume, network, and media bar widgets, or `noctalia msg panel-toggle control-center audio`).

Keyboard navigation uses the global [`[keybinds]`](/noctalia/configuration/shell/#keybinds) actions: `tab_next` / `tab_previous` switch between the sidebar and the active tab body; arrow keys move within the focused pane.

```toml
[control_center]
sidebar = "compact"
# sidebar_section = "compact"  # optional; defaults to the same as sidebar
# width = 700  # full-sidebar width in pixels (600–1200)
# show_shortcut_labels = true  # text under Home shortcut icons
# show_session_button = true   # Power tab button in the Home header
# hidden_tabs = ["monitor", "weather"]  # hide tabs you never use
```

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `sidebar` | string | `"compact"` | Sidebar on Home / general open: `"full"`, `"compact"`, or `"none"` |
| `sidebar_section` | string | `"compact"` | Sidebar when opening straight to a tab: `"full"`, `"compact"`, or `"none"` |
| `width` | int | `700` | Control Center width in pixels (`600`–`1200`). This is the full-sidebar width; the compact and no-sidebar modes scale down from it. |
| `show_shortcut_labels` | bool | `true` | Show text labels under Home shortcut icons. When `false`, shortcuts are icon-only and glyphs scale with cell size; hover still shows the name. |
| `show_session_button` | bool | `true` | Show the Power tab button in the Home tab header. |
| `hidden_tabs` | array | `[]` | Tab [context IDs](#sidebar-tabs) to hide from the Control Center. Empty shows every available tab. Editable from **Control Center → Control Center**. The Home tab cannot be hidden. |

The full sidebar shows group captions: **Appearance** (theme, type, scale, roundness, effects, language, wallpaper, templates), **Desktop** (bar, dock, desktop, windows, panels, OSD), **Device** (network, bluetooth, audio, media, displays, power, notifications, screen time, calendar, weather, camera, system), **Services** (privacy, firewall, security, printers, cast, Phone, Syncthing, packages, and similar tools), **Input** (launcher, keybinds, shell), then **General** (Control Center, niri, hooks, plugins). Compact mode uses separators between those groups instead of captions.

Plugin Control Center tabs stay in **Services**. User `hidden_tabs` still hide any tab in every group.

## Home

The Home tab is the Control Center landing view: clustered glass shortcut islands plus a compact status column. Other tabs are Settings pages with live controls.

When something needs attention, a status row appears between the user card and the media/clock cards: pending package updates (opens Packages), an active recording or replay buffer (opens Capture → Record), night light currently warming the display (opens Monitor), caffeine/idle-inhibit on (opens Power), and an incoming LocalSend transfer waiting to be accepted (opens LocalSend). The row hides when everything is idle. Shortcuts stay for actions; the chips only report state.

Click the avatar to pick a custom image, or the rest of the user card to open **Wallpaper**. Click the media card to open **Media**; with nothing playing it stays a single compact row so the clock and weather keep the leftover height. Click the date or time to open **Calendar** (including the world-clock card). Click the weather line to open **Weather**. Hover any of those regions for a tooltip. Noctalia saves the selected avatar path as `[shell].avatar_path`.

When AccountsService is available, Noctalia also writes the selected avatar to `org.freedesktop.Accounts` as your user's `IconFile`. That is what Noctalia Greeter reads for the login user list. On distros where this is not enabled by default, install and enable **accountsservice** (usually the `accounts-daemon` service) if you want the same avatar in both the shell and the greeter.

The shortcut buttons are configured separately; see [Control Center shortcuts](/noctalia/control-center/shortcuts/).

Header gear opens Home shortcut buttons, shortcut labels, and the session-button setting. Layout, sidebar mode, width, and hidden tabs stay on the **Control Center** tab in Advanced (`noctalia msg panel-toggle control-center control-center` or `noctalia msg settings-toggle control-center`). `noctalia msg settings-toggle` with no section still opens Theme.

Set `show_session_button = false` under `[control_center]` to hide the Power button in the Home tab header. Hover the header button for **Open Power**. This does not affect Home shortcuts configured with `type = "session"` or session widgets on the bar. The header button and the `session` shortcut open the Power tab; custom session actions stay on the session panel behind Power's gear.

## Theme

The Theme tab is the landing page for colors, grouped like a Settings form. Dark, Light, or Auto and the separate shell-mode dropdown share one well with Pure Black. Palette source, picker, save-as-custom, and role swatches share the next. Tap a swatch to customize that role for the current light or dark mode; the shell saves a custom palette and switches to it. On niri, window decorations and compositor blur have their own well.

Font, scale, corner radius, effects (contrast, motion, borders, shadows), and language each have their own tab next to Theme.

## Language

The Language tab sets the shell UI language. Auto follows the system locale. Otherwise pick a supported translation. Untranslated strings fall back to English.

`noctalia msg panel-toggle control-center language` opens this tab. `noctalia msg settings-toggle language` opens the same page.

## Effects

The Effects tab is the live page for visual treatment that is not color. Panel chrome (Solid, Soft, Glass) keeps its own well with a trailing dropdown. High contrast, application icon tint, motion, borders, and popup shadows share the next well, with hairlines between those groups. Animation speed hides when motion is off. Shadow direction and opacity hide when popup shadows are off. The color picker hides when icon tint is off.

`noctalia msg panel-toggle control-center effects` opens this tab.

## Wallpaper

The Wallpaper tab is the same picker used by the dedicated wallpaper panel: a thumbnail grid from your configured folders, Wallhaven search, a Video source, a Daily Bing/NASA source, and a folder button to choose any image. Library, Wallhaven, Video, and Daily share one compact card. Icon sources, search, and that source's tools sit on the left; the current wallpaper, Display, star, and lock-screen sit on the right. The grid sits under the card. Flatten, sort, color, and Wallhaven filters open from the Filters control. Theme-from-wallpaper controls appear in the same card when that wallpaper is starred. Empty, error, and download status use a caption in the card. Video runs `mpvpaper` directly; `mpvpaper` must be installed.

Header gear opens wallpaper settings: fill mode, directories, per-monitor folders, automation, the Wallhaven API key, Daily source, and on niri the overview wallpaper preset (none, blurred backdrop, stationary, or a flat color) plus backdrop blur/tint. `noctalia msg settings-toggle wallpaper` opens that settings view. The floating wallpaper panel remains available from the bar widget and `noctalia msg panel-toggle wallpaper`. `noctalia msg panel-toggle wallpaper daily` (or `bing` / `nasa`) opens Daily on that panel; `noctalia msg panel-toggle control-center wallpaper daily` does the same in Control Center.

## Templates

The Templates tab browses app-theme templates the same way Wallpaper browses images. Icon sources, Enable, and catalog status share one compact card; the grid sits under it. Hover Built-In, Community, and User. Built-In and Community keep Enable on the right of that card; User hides it. Search, Filters, and sort sit with the grid. Enabling a template applies it on each theme change. Header **Apply** rerenders every enabled template for the current palette (`noctalia msg templates-apply`).

The header **+** button picks an installed application. If a built-in or community template matches that app, Noctalia enables it. Otherwise it scaffolds a user template under `~/.config/noctalia/templates/` and opens the starter file so you can map tokens to the app's theme format. A sheet then asks for the output path the application actually reads, plus an optional post-hook. On the User catalog, each tile's gear edits those fields or deletes the GUI-created entry (starter files stay on disk). The header folder button opens that templates directory.

When Noctalia Greeter is installed, header gear has **Sync Now** and **Auto-Sync** to copy wallpaper, colors, and monitors to the login screen. Built-in catalogs also offer a GTK Templates row when GTK templates are off.

Palettes stay on **Theme**.

Header gear opens greeter sync when it is available. `noctalia msg settings-toggle templates` opens that settings view. Community catalog search from a settings search still offers **Browse Templates** as a sheet.

## Keybinds

The Keybinds tab is niri compositor shortcuts. Top tabs switch between **Attention**, **Open**, **Apps**, **Capture**, **Sound**, and **Session**. Unfinished rows (missing, or a recommended key taken in your own `binds { }`) live on **Attention** and also remain in their category; that tab hides when the inbox is empty. Search shows matches from every section. Keys that only exist in an included stock file such as Fedora's `default-config.kdl` are not treated as taken: **Add** writes them into `noctalia-binds.kdl` last, so they override the stock action. Missing rows stay unset until you record a chord. Restore puts a managed custom chord back on the recommended key; Remove drops it from `noctalia-binds.kdl` only.

**Apps** are niri `spawn` binds, not Helix IPC. Add an installed application, then record a chord. Those lines stay in `noctalia-binds.kdl` with the rest of the managed binds.

Header **Copy missing**, **Add to niri**, **Restore recommended**, and **folder** copy missing niri binds, install them, reset managed keys, or open the niri config directory. Media, volume, and brightness binds are written with `allow-when-locked=true`. Existing `binds { }` entries are left unchanged.

In-panel navigation (Enter, Escape, arrows, Tab) still uses the defaults. Header gear exposes those as **In Helix Shell**. `noctalia msg settings-toggle keybinds` opens that settings view.

## Media

The Media tab shows active players and playback controls independent of any bar media widget. It is useful when multiple players are running or when artwork and track metadata need more room than a bar capsule can provide.

## Audio

The Audio tab groups PipeWire output, input, device, and stream controls. Use it for volume changes, muting, selecting devices, and inspecting application streams without opening an external mixer. Microphone, camera, and screen-share captures live on [Privacy](#privacy).

## Monitor

The Monitor tab lists connected displays. On niri, **Arrangement** is a canvas of screen-shaped tiles at their real aspect ratios. The origin display shows a menu-bar strip; drag that strip onto another tile to move the origin. Click a tile to inspect it below. Night Light sits under that canvas when the compositor supports gamma control. The selected display has identity, brightness, Main display, enable, resolution, refresh rate, scale, rotation, and VRR. Brightness sliders appear when a writable backlight is available (including DDC/CI when that is enabled). Disabled displays stay listed so you can turn them back on.

niri only keeps the cursor path between **adjacent, non-overlapping** outputs. A layout change that overlaps another display is rejected and niri auto-places that output to the far right, which jumps windows with it. The Monitor tab pins every enabled output's position on each change so niri does not auto-place the ones you did not move.

Drag a display to another side, including directly above or below. A small drag along a shared edge still slides. Drag far enough off that edge to sit against the new side. The arrows place the selected display above, below, left, or right. Pick **Relative to** when three or more are on.

Live niri changes apply through compositor IPC. Use the header **Save to niri** button to write the current layout (mode, scale, transform, position, VRR, off) to `noctalia-outputs.kdl` and include it from `config.kdl`. niri reloads that file on its own, so the layout survives compositor restarts. The header refresh button re-reads the current output state (and re-runs DDC/CI detect when that backend is enabled).

## Camera

The Camera tab is a stage plus inspector, the same split Camera Hub and Logitech Capture use: the live frame stays visible while you change the picture. Zoom, pan, and tilt sit under the preview. Picture, Exposure, White Balance, and Focus are grouped on the right, with Auto on each section header gating the manual slider. When the panel is too narrow, the inspector moves under the preview. The preview shows the full frame (it is not cropped). Header reset restores factory values. If a device has no preview stream, its controls stay available.

## System

The System tab summarizes the machine and live resource usage. It shows distribution/kernel details, board/CPU/GPU information, uptime, install age, load averages, memory and swap, and graphs driven by the shared system monitor service. The header copy button places that summary on the clipboard.

System monitor sampling is configured globally under `[system.monitor]`; see [System monitor](/noctalia/services/system-monitor/).

## Network

The Network tab uses the configured network backend to show wireless state and connection details. It is the destination for Wi-Fi shortcuts and network-related right-click actions.

The current connection line lists the IPv4 address, signal strength, radio band, and external IP. The band (`2.4 GHz`, `5 GHz`, `6 GHz`, or `60 GHz`) is shown only when the backend reports the connection frequency: NetworkManager and wpa_supplicant do, iwd does not.

The current connection card also shows live throughput (when the system monitor is running), the nameservers from `/etc/resolv.conf`, and a trailing DNS dropdown for the active NetworkManager connection: **Automatic** (DHCP), **Google**, **Cloudflare**, **NextDNS**, or **Custom**. Presets apply immediately. NextDNS can take an optional config ID; Custom takes a comma-separated list of IPv4/IPv6 addresses and an Apply button. Changing DNS updates the connection profile and reapplies it; Noctalia does not write `/etc/resolv.conf`. iwd and wpa_supplicant backends cannot set DNS from here.

The current connection card also has icon tools to ping, copy the LAN IPv4 address, run a short download speed test, or share the current Wi-Fi network as a QR code and join string. Hover each tool. Sharing copies a `WIFI:` payload with the SSID. On NetworkManager, the stored PSK is included when GetSecrets can return it; otherwise the QR still starts the join flow and the other device asks for the password. 802.1X networks never embed a password.

Wi-Fi, VPN, and cellular lists sit under that card so they keep the leftover height.

Header gear opens Network settings: Wi-Fi band filter and ignored SSIDs. Dual-band networks are listed once (the strongest BSS), so a 5 GHz filter hides a network whose strongest copy is on 2.4 GHz. iwd access points have no frequency and stay visible only when the band filter is **All**.

`[control_center.network]` holds those Network tab options:

```toml
[control_center.network]
wifi_band = "all"       # all | 2.4 | 5 | 6
hidden_ssids = []
nextdns_id = ""
custom_dns = ""
```

### Enterprise Wi-Fi (802.1X)

Clicking a WPA2/WPA3-Enterprise network opens a credential form instead of the pre-shared-key field: EAP method (PEAP or TTLS), inner authentication, identity, anonymous identity, server domain suffix, and CA certificate path. The password field below the form is the one used for the EAP login.

PEAP accepts MSCHAPv2 only, so the inner dropdown is pinned and disabled while PEAP is selected; TTLS also allows PAP, MSCHAP, and CHAP. Leaving the CA certificate path empty trusts the system CA store; a path must be absolute and pins that file instead of the system store. The server domain suffix is the RADIUS server name suffix your organization publishes, and is optional.

Enterprise networks are recognized on the NetworkManager backend only; the wpa_supplicant and iwd backends still show the pre-shared-key prompt for them, which an 802.1X network cannot accept. Certificate-based EAP-TLS, including WPA3-Enterprise 192-bit, is not supported: the form says so instead of writing a profile NetworkManager would reject. Use `nmcli` or another NetworkManager front end for those networks.

### Cellular

When ModemManager reports a modem, the Network tab adds a **Cellular** card with a mobile-data switch and one row per modem showing its operator (or hardware name), state, access technology (`5G`, `LTE`, `HSPA+`, ...), and signal percentage. The card disappears again when ModemManager stops or the modem is unplugged.

The switch follows GNOME's mobile-data semantics: with a saved NetworkManager `gsm` profile it turns the data connection on and off and leaves the modem registered on the network; with no such profile it powers the modem radio itself. Turning it on can take several seconds while the modem enables, searches, and registers, and the switch holds the requested position until the change lands.

Cellular needs ModemManager running (`org.freedesktop.ModemManager1`) and, for mobile data, a `gsm` connection profile created with `nmcli` or another NetworkManager front end. Noctalia does not create or edit cellular profiles.

## Bluetooth

The Bluetooth tab shows adapter power, discoverable, and rescan on one compact card. Device lists sit under that card so they keep the leftover height. Expand a device to copy its Bluetooth address. It is backed by Noctalia's Bluetooth service and agent. Header gear opens unnamed-device hiding and how long **Rescan** keeps discovery running.

```toml
[control_center.bluetooth]
hide_unnamed = false
discovery_seconds = 10
```

## Capture {#capture}

The Capture tab combines screenshots and screen recording in one Services page with **Screenshot | Record** segments. Hover a segment for what it does. Contexts `screenshot` and `screen-record` (and `settings:screenshot` / `settings:screen-record`) still open the matching segment. Hiding either legacy id in `hidden_tabs` hides the whole Capture tab.

### Screenshot {#screenshot}

The Screenshot segment starts a region capture, fullscreen capture, a display picker, a screen color picker, an annotation overlay, or a text/QR scan. Choose **Now**, **3s**, or **5s** before a capture if you need time to hide Control Center chrome (hover a delay for the wait). The countdown stays on the tab, then Control Center closes so the overlay can take the screen. **Scan text** needs [`tesseract`](https://github.com/tesseract-ocr/tesseract); **Scan QR** needs `zbarimg` from [ZBar](https://github.com/mchehab/zbar). Both copy the result to the clipboard. Recent PNG files from the save folder appear under **Recent screenshots** with thumbnails; click a name to open it, **Annotate** to draw on that still, or trash (click twice) to delete it. **Open screenshot folder** launches the configured save directory. Color pick follows the pointer with a magnifier, swatch, and `#RRGGBB` value, then copies on click. Header gear opens the existing screenshot capture, annotation, and output settings.

### Screen Record {#screen-record}

The Record segment starts and stops a recording without the official plugin. Control Center closes first so it is not in the video. **Focused** records the active monitor. **Region** is shown when `wf-recorder` is installed and uses the same overlay as screenshots. **Portal** is shown when `gpu-screen-recorder` is installed and opens the desktop portal picker. Hover a source or delay for what it does. Use the delay control (Now / 3s / 5s) when you need Control Center fully gone before capture starts. Elapsed time appears while a recording is running. If no recorder is installed, the tab tells you to install one. Recent `.mp4` files from the save folder appear under **Recent recordings**; click a name to open one, or trash (click twice) to delete it. Header gear opens `[shell.screen_record]` for the save folder, filename pattern, audio, cursor, and replay duration.

A **Replay buffer** card starts `gpu-screen-recorder` in replay mode (`-r`) the same way Record starts a capture. Start the buffer, then **Save replay** writes the last N seconds without stopping it. **Stop replay buffer** ends the process without saving. Replay needs `gpu-screen-recorder` (native or Flatpak `com.dec05eba.gpu_screen_recorder`); region source is not used for replay. Record and replay cannot run at the same time.

Install `gpu-screen-recorder` and/or `wf-recorder`. The optional [`noctalia/screen_recorder` plugin](/noctalia/plugins/official-plugins/#screen_recorder) still offers codec and quality settings if you prefer that recorder.

## Clipboard

The Clipboard tab is the clipboard history view: filter, pin, copy, delete, and preview text or images. Hover the preview icons for pin, copy, delete, and the optional image action. Header gear opens `[shell]` clipboard settings (history, auto-paste, and the image action). The bar widget, the Home clipboard shortcut, and `noctalia msg panel-toggle clipboard` open this tab.

## Tailscale

The Tailscale tab talks to the local `tailscale` CLI. Connect and disconnect this machine, copy its tailnet addresses, open the admin console, and toggle shields, subnet routes, SSH, DNS, advertising an exit node, and LAN access while using an exit node. Status, preferences, and the peer list share one grouped well. Pick an exit node from the dropdown, or use a peer as an exit from the device list. Mullvad exit nodes stay in the exit picker and are omitted from the peer list.

Connect, disconnect, and preference writes need Tailscale operator access. If this user is not the operator, Noctalia asks for an administrator password (via `pkexec` and the built-in Polkit prompt) and retries. To skip that prompt later, run `sudo tailscale set --operator=$USER` once.

The tab stays visible when `tailscale` is not installed, with a message to install it. Header gear opens `[tailscale]` for poll interval, optional peer online/offline toasts, and an admin URL override. Daemon prefs are applied with `tailscale set` and are not stored in `settings.toml`.

The community plugin's bar widget and `panel-toggle davemhammer/tailscale:manager` keep working. If that plugin later registers a Control Center tab, the built-in page replaces it.

```toml
[tailscale]
refresh_interval_seconds = 10
notify_on_peer_change = false
# admin_url = ""
```

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `refresh_interval_seconds` | int | `10` | How often to poll `tailscale status` (3–120). |
| `notify_on_peer_change` | bool | `false` | Toast when a tailnet peer comes online or goes offline. |
| `admin_url` | string | `""` | Admin console URL. Empty uses Tailscale's default, or the login URL when this machine needs authentication. |

IPC: `tailscale-up`, `tailscale-down`, `tailscale-toggle`, and `tailscale-status`. See [Media & UI](/noctalia/ipc/media-and-ui/#tailscale).

## LocalSend

The LocalSend tab is a native LocalSend peer: it announces this machine on the LAN (`224.0.0.167:53317` by default) and speaks the HTTP REST API so nearby LocalSend apps can send files here. Turn nearby sharing on from the live view. Turning it off leaves the enable switch. Incoming transfers wait for **Accept** or **Decline** unless auto-accept is on; Home also shows a status chip while a transfer is waiting. Send a file, a folder (up to 64 files, three folders deep, hidden names skipped), or the clipboard to a discovered device. The live view shows file-of-file progress and a recent history list for this session. If that device requires a PIN, enter it in the field on this tab first.

This machine advertises `http` so receive does not need a TLS certificate. Sending still talks HTTPS when the other device requires it. If another LocalSend app already bound TCP port 53317, this tab can still send; receiving stays blocked until that port is free or you pick a different port in settings.

Header gear opens `[localsend]` for the device name, receive PIN, download folder, auto-accept, receive toasts, and port.

```toml
[localsend]
enabled = true
# alias = ""
# pin = ""
# download_dir = "~/Downloads"
auto_accept = false
notify_on_receive = true
port = 53317
```

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `enabled` | bool | `true` | Advertise on the LAN and accept LocalSend transfers. |
| `alias` | string | `""` | Name shown to other devices. Empty uses this machine's hostname. |
| `pin` | string | `""` | Optional PIN other devices must enter before sending files here. |
| `download_dir` | string | `""` | Folder for received files. Empty uses `~/Downloads`. |
| `auto_accept` | bool | `false` | Accept incoming files without asking. |
| `notify_on_receive` | bool | `true` | Toast when someone offers or finishes sending files here. |
| `port` | int | `53317` | TCP and UDP LocalSend port (`1024`–`65535`). |

IPC: `localsend-toggle`, `localsend-status`, and `localsend-announce`. See [Media & UI](/noctalia/ipc/media-and-ui/#localsend).

## Phone

The Phone tab talks to the session KDE Connect daemon (`org.kde.kdeconnect`). Status and the device list share one grouped well. Pair a phone running KDE Connect, then ping it, ring it, send a file, or send the clipboard. Battery percent shows when the phone reports it. Unpaired nearby devices get a Pair button; an incoming pair request shows Accept and Decline plus the verification code.

The tab stays in the sidebar when KDE Connect is not installed. **Start KDE Connect** asks D-Bus to launch the daemon if the package is present. Opening the tab also asks the daemon to look for nearby devices; closing the tab stops that scan.

Helix does not replace KDE Connect's own pairing UI on the phone. Install the KDE Connect app on the other device and keep it on the same network.

IPC: `phone-status`, `phone-ping`, and `phone-ring`. See [Media & UI](/noctalia/ipc/media-and-ui/#phone).

The tab stays in the sidebar when Syncthing is not installed. Adding folders and devices stays in the Syncthing UI.

## Firewall

The Firewall tab talks to firewalld (`org.fedoraproject.FirewallD1`). Status, the default zone, and incoming services share one grouped well. Pick the default zone, toggle incoming services such as Remote login and KDE Connect, and use **Block all traffic** for panic mode. Changes apply immediately to the running firewall. **Save for next boot** copies that runtime config to disk.

The tab stays in the sidebar when firewalld is not installed. **Start firewall** asks systemd to start `firewalld.service` and may show a password prompt.

## Calendar

The Calendar tab shows the month view, a world clock of extra IANA timezones, accounts (add, edit, reconnect), and events from those accounts. Turning calendar sync off leaves the enable switch on the accounts card. Calendar accounts and sync behavior are documented under [Calendar](/noctalia/services/calendar/).

Right-click a day to launch the application registered for the `text/calendar` MIME type. The Calendar panel closes
after a successful launch.

`[control_center.calendar]` holds how the tab is drawn; `[calendar]` holds whether events are synced and the shared event date and time formats.

```toml
[control_center.calendar]
show_events_card  = true
show_week_numbers = false       # ISO 8601 week numbers in the month grid
timezones         = []         # IANA names for the world-clock card, e.g. "America/Los_Angeles"
```

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `show_events_card` | bool | `true` | Show the event list beside the month grid. Also toggled from the calendar button in the tab header. |
| `show_week_numbers` | bool | `false` | Show a column of ISO 8601 week numbers to the left of the month grid, separated from it by a divider. Each row is numbered by the week its Thursday falls in. |
| `timezones` | string array | `[]` | Extra IANA timezones on the world-clock card. Search and pick them from the live card, or edit the list in Calendar settings. Times use `[shell].time_format`. |

The shared `event_date_format` and `event_time_format` options are documented under [Calendar](/noctalia/services/calendar/).
Week numbers are a decoration of the month grid, so they work with `[calendar].enabled = false` and no accounts configured.

## Screen Time

The Screen Time tab shows how long each application was in the foreground today. Noctalia tracks focus using the active `zwlr_foreign_toplevel` window, pauses tracking while its session lock is active, and stores daily totals under `$XDG_STATE_HOME/noctalia/screen_time.json` (about 14 days retained).

When tracking is off, the tab shows a disabled banner with the enable toggle on that same live view.

- **Range** toggle: today (hourly chart), last 3 days, or last 14 days (daily bars)
- **Total** time for the selected range, with a stacked bar chart (hourly or per-day)
- **Chart legend** as a horizontal row under the chart (chart colors only; app list uses neutral bars)
- **Most used** apps with icons, usage bars, and duration for the selected range

Open it from the control center sidebar (`screen-time` context) or add a Home shortcut with `type = "screen_time"`.

Reset stored history from the Screen Time tab header gear (**Screen Time** settings) or **System → Screen Time → Reset Screen Time Data**. That clears `screen_time.json` while Noctalia is running.

## AI

The AI tab shows coding assistants and local inference on this machine. Assistants follow the same local data sources as the community [AI Usage Tracker](https://github.com/JakubSx01/ai-usage-tracker) plugin: each provider is auto-detected from sign-in files or an installed app/CLI, then queried with your existing credentials. **Open** launches the matching desktop entry, or a terminal for CLI tools.

| Provider | Detected from | Data |
|----------|---------------|------|
| Claude Code | `~/.claude/.credentials.json` or `claude` | Anthropic OAuth usage (5 h and 7 day windows) |
| Cursor | Cursor `state.vscdb` + `sqlite3`, or the Cursor app | `cursor.com/api/usage` premium request quota |
| Codex | `~/.codex/sessions` or `codex` | `rate_limits` from the newest session `.jsonl` |
| Gemini CLI | `~/.gemini` or `gemini` | Today's prompts vs a configurable daily quota |
| Qwen Code | `~/.qwen` or `qwen` | Today's prompts vs a configurable daily quota |
| GitHub Copilot | `~/.config/github-copilot` + `gh` | Copilot quota snapshots |
| DeepSeek | DeepSeek API key in the environment | Prepaid balance (no percentage) |

**Ollama** appears when the `ollama` CLI is on `PATH` (or always-on in settings). The card shows running/stopped, installed models, and which are loaded. Start uses `systemctl --user start ollama`, then `ollama serve` if that unit is missing. Stop uses the user unit (and a serve process Noctalia started). A remote `ollama_host` lists models only.

Tokens stay on this machine except for requests to that provider's own API. A failed refresh keeps the last good numbers. Open the tab with `noctalia msg panel-toggle control-center ai` (`ai-usage` is an alias). Header gear is `[control_center.ai_usage]`:

```toml
[control_center.ai_usage]
refresh_seconds = 120          # 30–900
claude = "auto"                # auto | on | off
cursor = "auto"
ollama = "auto"
# ollama_host = "127.0.0.1:11434"
# gemini_daily_limit = 1000
# qwen_daily_limit = 2000
```

## Settings

Settings pages are Control Center tabs. Theme, Type, Scale, Roundness, Effects, Language, Wallpaper, and Templates sit under **Appearance**. Bar, Dock, Desktop, Windows, Panels, and OSD sit under **Desktop**. Network, Bluetooth, Audio, Media, Monitor, Power, Notifications, Screen Time, Calendar, Weather, Camera, and System sit under **Device**. Privacy, Firewall, Security, Printers, Cast, and similar tools sit under **Services**. Launcher, keybinds, and shell sit under **Input**. Control Center options, niri, hooks, and plugins sit under **General**.

Domain options that belong with a live view are on that tab: theme and palette on Theme (Auto shows the next day/night switch; community and custom palettes use a searchable picker), language on Language, font on Type, UI scale on Scale, corner radius on Roundness, panel glass, high contrast, icon tint, motion, borders, and shadows on Effects, greeter sync under Templates gear, the wallpaper picker on Wallpaper (header gear for folders, Wallhaven, and on niri overview wallpaper), location, units, and Weather enable under Weather gear (enable also on the compact-off card), night light on Monitor (force and temperatures when on), lock/suspend/logout/reboot/shutdown/caffeine on Power, world clock on Calendar, privacy captures plus approximate location and the startup ping on Privacy (header gear for capture-name filters), the enable toggle on Screen Time, Network DNS and Wi-Fi QR on Network, capture buttons on Capture, dock enable/position/auto-hide/pins on Dock (header gear for size, shape, and magnification), desktop widgets/corners on Desktop, launcher pins and always-in-search providers on Launcher (header gear for appearance, placement, prefixes, auto-paste, and currency), Home shortcuts behind the Home header gear, and header gear on Notifications, Power, System, Calendar, Audio, Monitor, Media, Bar, Bluetooth, Network, Capture, Screen Time, and AI for the longer forms.

Each settings page is searchable from the sidebar field above Home (or from the header when the sidebar is hidden). Press `/` or Ctrl+F to focus the field. An empty query keeps that page’s filter. A tab name (for example `calendar`) filters the sidebar and opens that live page; the same query is kept for that tab’s settings, so the header gear shows matching rows. Other queries search the settings registry on the current tab’s gear sheet when that section matches. If it does not, Control Center opens the best matching section in gear mode instead of always dumping onto Theme.

The plugin store, session/idle editors, notification filters, calendar accounts, community templates, and bar widget inspectors open as sheets in Control Center. The header Advanced toggle shows advanced settings. The ⋮ menu on a settings page exports config and saves a support report.

Open Theme with `noctalia msg panel-toggle control-center settings` or `noctalia msg settings-toggle`. Pass a section to land on that page, for example `noctalia msg settings-toggle bar` or `noctalia msg settings-toggle location` (Weather tab). `settings-toggle` without a section still lands on Theme. `appearance` is an alias for Theme.

The Niri and Windows pages are shown only when the session is running under niri. Theme owns decorations and compositor blur; Windows owns gaps, outer padding, and column width; Wallpaper owns overview presets and backdrop; Launcher owns type-to-launch.

## Power

The Power tab consolidates session actions and power-management status, backed by UPower and `power-profiles-daemon`:

- **Session** - lock, suspend, logout, reboot, shutdown, and caffeine (keep awake). Reboot and shutdown use the destructive style. Custom session actions and countdown confirmation stay on the session panel.
- **Battery** - charge percentage, charging/discharging state, time remaining (or time until full), and current draw in watts
- **Power Profile** - a selector for the profiles your machine exposes (power-saver, balanced, performance); switching here is equivalent to the Home shortcut and bar widget
- **Battery Health** - current full-charge capacity as a percentage of the original design capacity
- **Connected Devices** - battery levels for peripherals such as Bluetooth mice, keyboards, and headsets

Sections appear only when their data is available: the battery and health sections require a system battery, the profile selector requires `power-profiles-daemon`, and the connected-devices section appears when peripherals report a battery. The tab itself is hidden on systems where neither UPower nor `power-profiles-daemon` is running.
