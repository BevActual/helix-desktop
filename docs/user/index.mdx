Helix is a niri-first desktop: **greetd → helix-greeter → helix-niri + Helix Shell**. This tree is Helix Shell, a native Wayland runtime with Control Center, first-party services, and a configuration model built for that desktop. The command and config paths stay `noctalia`. Stock niri, Hyprland, and other compositors remain fallbacks.

If you are setting up Helix for the first time, start with [Installation](/noctalia/getting-started/installation/), then [Running Helix](/noctalia/getting-started/running-the-shell/) for compositor startup and keybind setup. Once the shell is installed, [How configuration works](/noctalia/configuration/) explains where settings live and which file wins when the GUI and your config both set the same option.

:::caution[Coming from Noctalia v4?]
- Helix Shell (and Noctalia v5) install separately and do not replace v4.
- v4 settings are not migrated, but both versions can coexist on most distributions.
- Update any compositor keybinds that launch `noctalia` commands.
:::
