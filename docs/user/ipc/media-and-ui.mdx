These commands control user-facing shell features that are not tied to one persistent surface.

## Notifications

| Action | Command | Description |
|--------|---------|-------------|
| Enable Do Not Disturb | <IpcCommand command="notification-dnd-set on" /> | Hide current notification toasts and suppress new ones. Notification history still fills. |
| Disable Do Not Disturb | <IpcCommand command="notification-dnd-set off" /> | Allow new notification toasts; hidden or suppressed toasts are not replayed. |
| Toggle Do Not Disturb | <IpcCommand command="notification-dnd-toggle" /> | Toggle notification toast suppression. Notification history still fills. |
| Show Do Not Disturb status | <IpcCommand command="notification-dnd-status" /> | Print the current Do Not Disturb state. |
| Send internal notification | <IpcCommand command="notification-show <summary>" /> | Create a Helix-origin notification with the provided summary text. |
| Invoke latest notification | <IpcCommand command="notification-invoke-latest" /> | Invoke the default action of the most recent active notification (raises/focuses the source app), mirroring a toast left-click. |
| Clear active notifications | <IpcCommand command="notification-clear-active" /> | Dismiss all currently visible active notifications. Dismissed notifications stay in control-center history. |
| Clear notification history | <IpcCommand command="notification-clear-history" /> | Remove all entries from notification history. |

DND enable/disable IPC commands show a short OSD for the new state.

`notification-show` accepts a summary, and CLI usage can pass body as a second argument:

```sh
helix-panel notification-show "Build finished"
helix-panel notification-show "Build finished" "All tests passed"
```

When a body argument is passed, the CLI forwards it as structured payload (`summary` + `body`) to the IPC handler.

For full control, pass a JSON payload object:

```sh
helix-panel notification-show '{"app_name":"Helix","summary":"Build finished","body":"All tests passed","urgency":"low","timeout_ms":4000,"icon":"circle-check"}'
```

Supported JSON fields:

- `app_name` (string): application label shown for the notification (default `Helix`)
- `summary` (string, required for JSON mode): notification title text
- `body` (string): body text
- `urgency` (string): one of `low`, `normal`, `critical`
- `timeout_ms` (integer): auto-dismiss timeout in milliseconds (`0` keeps it persistent)
- `icon` (string): icon hint. Plain names are treated as Helix glyphs (for example `circle-check`), while paths and URLs are treated as image icons.
- `category` (string): freedesktop category
- `desktop_entry` (string): desktop entry id

## Clipboard

| Action | Command | Description |
|--------|---------|-------------|
| Clear clipboard history | <IpcCommand command="clipboard-clear" /> | Clear clipboard history without opening the Clipboard tab. Pinned entries survive, so with nothing pinned this clears everything. Does not ask for confirmation. The live selection is untouched; pasting still works until something else is copied. |
| Copy text to clipboard | <IpcCommand command="clipboard-copy <text>" /> | Set the clipboard selection to `<text>`. Everything after the verb is the payload, so spaces and newlines are kept verbatim. Payloads are capped at 64 KiB by the IPC transport. |
| Print clipboard text | <IpcCommand command="clipboard-text" /> | Print the most recent clipboard text on stdout with no trailing newline. Pinned entries and images are skipped, so this matches what pasting into a Helix input would insert. Prints nothing when the history holds no text. |

## Media

|--------|---------|-------------|
| Previous track | <IpcCommand command="media previous" /> | Ask the active MPRIS player to go to the previous item. |
| Next track | <IpcCommand command="media next" /> | Ask the active MPRIS player to go to the next item. |
| Play/pause toggle | <IpcCommand command="media toggle" /> | Toggle play/pause on the active MPRIS player. |
| Play | <IpcCommand command="media play" /> | Resume playback on the active MPRIS player. |

Use `media pause` to pause without dismissing. |
| Raise player | <IpcCommand command="media raise" /> | Raise the active MPRIS player window. |
| Previous player | <IpcCommand command="media previous-player" /> | Switch the active player to the previous available MPRIS player and pin it. |
| Next player | <IpcCommand command="media next-player" /> | Switch the active player to the next available MPRIS player and pin it. |

## Wallpaper

| Action | Command | Description |
|--------|---------|-------------|
| Random wallpaper now | <IpcCommand command="wallpaper-random" /> | Switch to a random wallpaper immediately on all monitors. |
| Random wallpaper (one monitor) | <IpcCommand command="wallpaper-random <connector>" /> | Switch to a random wallpaper on the monitor named by **connector** (e.g. `DP-1`). Other monitors are unchanged. Respects per-monitor directory configuration and theme mode. |
| Next wallpaper | <IpcCommand command="wallpaper-next" /> | Advance to the next wallpaper in order immediately on all monitors. |
| Next wallpaper (one monitor) | <IpcCommand command="wallpaper-next <connector>" /> | Advance to the next wallpaper on the monitor named by **connector** (e.g. `DP-1`). Other monitors are unchanged. Respects per-monitor directory configuration and theme mode. |
| Previous wallpaper | <IpcCommand command="wallpaper-previous" /> | Go back to the previous wallpaper in order immediately on all monitors. |
| Previous wallpaper (one monitor) | <IpcCommand command="wallpaper-previous <connector>" /> | Go back to the previous wallpaper on the monitor named by **connector** (e.g. `DP-1`). Other monitors are unchanged. Respects per-monitor directory configuration and theme mode. |
| Get wallpaper | <IpcCommand command="wallpaper-get" /> | Print the default wallpaper path persisted in `settings.toml`. |
| Get wallpaper (one monitor) | <IpcCommand command="wallpaper-get <connector>" /> | Print the effective wallpaper path for the monitor named by **connector** (e.g. `DP-1`). |
| Set wallpaper (all monitors) | <IpcCommand command="wallpaper-set <path>" /> | Set every connected monitor and the default wallpaper, persisted to `settings.toml` (per-monitor entries plus `wallpaper.default.path`). |
| Set wallpaper (one monitor) | <IpcCommand command="wallpaper-set <connector> <path>" /> | Set only the monitor named by **connector** (e.g. `DP-1`). Remaining tokens are joined as the path. Other monitors are unchanged. |

Wallpaper paths accept an image path (`~` expanded) or `color:#RRGGBB` / `color:#RRGGBBAA`. Non-color paths must exist at call time.

The CLI forwards everything after the command as one string (`helix-panel wallpaper-set ...`), so `helix-panel wallpaper-set DP-1 /home/you/My Pictures/wall.jpg` still yields a correct path when the shell passes separate arguments after the command.

## Theme

| Action | Command | Description |
|--------|---------|-------------|
| Get theme mode | <IpcCommand command="theme-mode-get" /> | Print the current resolved theme mode: `dark` or `light` (from `[theme].mode` or from the `[location]` schedule when mode is `auto`). |
| Toggle theme mode | <IpcCommand command="theme-mode-toggle" /> | Switch between dark and light theme mode (same as the bar control when `[theme].mode` is not `auto`). |
| Set theme mode | <IpcCommand command="theme-mode-set dark" /> | Persist `[theme].mode` in `settings.toml` and reload. Pass `dark`, `light`, or `auto` (example shows `dark`). |
| Get color scheme | <IpcCommand command="color-scheme-get" /> | Print the active palette selection as two tokens: `builtin Helix`, `wallpaper m3-content`, `community Oxocarbon`, or `custom MyScheme`. |
| Set color scheme | <IpcCommand command="color-scheme-set builtin Helix" /> | Persist `[theme].source` and the palette for that source, then reload. |
| Apply templates | <IpcCommand command="templates-apply" /> | Rerender the enabled configured theme templates for the current palette without changing theme mode or firing shell palette hooks. |

`color-scheme-set` accepts these source kinds:

- **builtin** - built-in palette name, such as `Helix`
- **wallpaper** - generator scheme, such as `m3-tonal-spot`, `m3-content`, `m3-fruit-salad`, `m3-rainbow`, `m3-monochrome`, `vibrant`, `faithful`, `soft`, `dysfunctional`, or `muted`
- **community** - community palette id
- **custom** - palette file name without `.json` under `~/.config/helix/palettes/`

## Screenshots

Requires compositor support for `wlr-screencopy-unstable-v1`. Uses the global `[shell.screenshot]` output policy (directory, filename pattern, freeze, save to file, clipboard, pipe command). See [Shell settings](/helix/configuration/shell/#shell-settings).

| Action | Command | Description |
|--------|---------|-------------|
| Region screenshot | <IpcCommand command="screenshot-region" /> | Start interactive region capture (drag to select; press **`[keybinds].cancel`** to dismiss). |
| Fullscreen screenshot | <IpcCommand command="screenshot-fullscreen" /> | Capture the focused monitor (compositor-selected output, active toplevel, keyboard focus, or recent pointer). |
| Fullscreen (pick monitor) | <IpcCommand command="screenshot-fullscreen pick" /> | Open the display picker on multi-monitor setups. On a single monitor, captures immediately. |
| Fullscreen (specific output) | <IpcCommand command="screenshot-fullscreen DP-2" /> | Capture one output without the picker. Pass the Wayland connector name (e.g. `DP-1`, `HDMI-A-1`) or a word-boundary match in the output description. |
| Fullscreen (all monitors) | <IpcCommand command="screenshot-fullscreen all" /> | One combined desktop PNG spanning every monitor. |
| Annotate a frozen screen | <IpcCommand command="screenshot-annotate" /> | Freeze every monitor and open the annotation editor over the frozen image. **Copy** and **Save** deliver the annotated PNG; **`[keybinds].cancel`** closes without delivering. |
| Pick a screen color | <IpcCommand command="screenshot-pick-color" /> | Freeze every monitor, then click a pixel to copy its `#RRGGBB` value. Hover shows a magnifier, swatch, and hex. **`[keybinds].cancel`** dismisses without copying. |
| Scan text | <IpcCommand command="screenshot-ocr" /> | Drag a region, then copy OCR text (`tesseract`) to the clipboard. |
| Scan QR | <IpcCommand command="screenshot-scan-qr" /> | Drag a region, then copy a QR code or barcode (`zbarimg`) to the clipboard. |
| Annotate the live screen | <IpcCommand command="annotate" /> | Transparent drawing overlay for presentations. Apps keep updating behind the ink; **`F`** freezes the screen under it and reveals Blur, Crop, Copy, and Save. |
| Annotate an image file | <IpcCommand command="annotate ~/Pictures/shot.png" /> | Open an image from disk in the editor instead of the screen. No screencopy support needed. |

In picker mode, choose a connector from the top bar on any screen, or click the desktop to capture the monitor under the cursor. Errors list available connector names when the selector is unknown.

`annotate <path>` edits a file instead of the screen. The image is decoded with the shell's own loader (PNG, JPEG, GIF, WebP, JPEG XL, ICO, SVG, and the other formats used for wallpapers and icons) and opens centered at its native pixel size on the focused output, scaled down when it does not fit. EXIF orientation is applied, so camera and phone photos open upright. Relative paths resolve against the directory the command ran in, and `~` expands. The pointer button stays disabled because no cursor was captured, and **Freeze** is not offered. **Copy** and **Save** deliver the annotated PNG, and **Done** applies the `[shell.screenshot]` output policy. Saving never overwrites the source: it writes a new PNG into the screenshot folder using the configured filename pattern.

Annotation tool keys (no modifier): **`m`** move, **`b`** brush, **`h`** highlighter, **`l`** line, **`a`** arrow, **`s`** rectangle, **`o`** circle, **`t`** text, **`n`** numbering, **`u`** blur, **`e`** eraser, **`c`** crop, **`f`** freeze (live overlay), **`p`** toggle the captured pointer, **`[`** and **`]`** change the current tool's size. **`Ctrl+Z`** undoes, **`Ctrl+Shift+Z`** and **`Ctrl+Y`** redo, **`[keybinds].copy`** copies, **`[keybinds].save`** saves.

The pointer button and **P** work the same in region, fullscreen, and frozen-screen editing. `[shell.screenshot].show_cursor` sets the initial choice; toggling does not change that setting. Only the pointer recorded inside the captured area can appear. Helix captures the cursor separately through `ext-image-copy-capture-v1` and composites it over the same cursor-free background for both choices. When separate cursor capture is unsupported or fails, the ordinary screenshot keeps the configured pointer choice, the button is disabled with an explanatory tooltip, and **P** shows the same explanation. In live annotation, freeze with **F** first.

`[shell.screenshot].close_on_copy` and `[shell.screenshot].close_on_save` default to `true`: a successful **Copy** or **Ctrl+C** (including a custom **`[keybinds].copy`** binding) and a successful **Save** or **Ctrl+S** (including **`[keybinds].save`**) close the editor. Set either to `false` to keep editing after that action. Failed copies and failed saves leave the editor open.

**Capture new region** in the toolbar discards the current edit, captures a fresh desktop region without the annotation overlay, and opens it in the editor with the same pointer control and remembered tool preferences. Starting from a captured image preserves the editor's current pointer choice. It is available in live, frozen, and image modes, regardless of `[shell.screenshot].annotate`. Cancelling region selection closes the capture.

Captured images have an inset **Outline** color-role border to distinguish the canvas from its surroundings. The border does not change the image size or appear in copied or saved images.

The toolbar carries a grab handle on its left edge: drag it to move the bar out of the way. Each output's position is remembered independently for later sessions and clamped to that output. Moving one toolbar does not reposition the others. Every control has a tooltip naming its shortcut. **S**, **M**, and **L** set the current tool's size to half, one, or twice its default weight, and the adjustments button next to them reveals the fine stepper (`-`, the current pixel size, `+`) for anything in between; fine values are kept, not snapped back to the nearest preset.

The live color is the swatch carrying a check mark, and the shape-fill button shows a struck-through paint roller while fill is off. Size and color are per tool, so each remembers its own weight and color. While a text caret is open, changing size or color restyles the text under the caret instead of only the next one, and touching any other control (a tool, undo, freeze, export) commits that text first.

## Screen recording {#screen-recording}

Built-in recording uses `gpu-screen-recorder` when installed (native, then Flatpak `com.dec05eba.gpu_screen_recorder`) and falls back to `wf-recorder`. Replay buffer start/stop/save also uses `gpu-screen-recorder` (`-r`). Settings live under [`[shell.screen_record]`](/helix/configuration/shell/#shell-settings), including `replay_duration`. This is independent of the `helix/screen_recorder` plugin.

| Action | Command | Description |
|--------|---------|-------------|
| Start recording | <IpcCommand command="screen-record-start" /> | Record the focused monitor. |
| Start (portal) | <IpcCommand command="screen-record-start portal" /> | Open the desktop portal picker (`gpu-screen-recorder` only). |
| Start (region) | <IpcCommand command="screen-record-start region" /> | Drag a region, then record it (`wf-recorder` only). |
| Stop recording | <IpcCommand command="screen-record-stop" /> | Stop and save the current recording. |
| Toggle recording | <IpcCommand command="screen-record-toggle" /> | Start or stop. Optional source: `focused`, `portal`, or `region`. |
| Start replay buffer | <IpcCommand command="screen-record-replay-start" /> | Start the replay buffer on the focused monitor. |
| Start replay (portal) | <IpcCommand command="screen-record-replay-start portal" /> | Start the replay buffer with the desktop portal picker. |
| Stop replay buffer | <IpcCommand command="screen-record-replay-stop" /> | Stop the replay buffer without saving. |
| Save replay | <IpcCommand command="screen-record-replay-save" /> | Write the last N seconds without stopping the buffer. |
| Toggle replay | <IpcCommand command="screen-record-replay-toggle" /> | Start or stop the replay buffer. Optional source: `focused` or `portal`. |

Control Center closes before a recording or replay buffer starts so it is not in the video. Stop recording sends `SIGINT` so the encoder can finish the file. Save replay sends `SIGUSR1`. Record and replay cannot run at the same time.

## Tailscale {#tailscale}

Built-in Tailscale control uses the local `tailscale` CLI. Settings live under [`[tailscale]`](/helix/control-center/#tailscale). The community plugin's bar widget and panel stay independent.

| Action | Command | Description |
|--------|---------|-------------|
| Connect | <IpcCommand command="tailscale-up" /> | Bring this machine online (`tailscale up`). |
| Disconnect | <IpcCommand command="tailscale-down" /> | Disconnect (`tailscale down`). |
| Toggle | <IpcCommand command="tailscale-toggle" /> | Connect or disconnect. |
| Status | <IpcCommand command="tailscale-status" /> | Print `running`, `stopped`, or `not-installed`. |

`tailscale-status` prints `not-installed` when the CLI is missing. When connected it includes hostname, IPv4, and the selected exit node. Connect and disconnect may prompt for an administrator password unless this user is the Tailscale operator (`sudo tailscale set --operator=$USER`).

## Firewall {#firewall}

Built-in Firewall control talks to firewalld on the system bus. There is no Helix config block; zones and services live in firewalld.

| Action | Command | Description |
|--------|---------|-------------|
| Status | <IpcCommand command="firewall-status" /> | Print `not-installed`, `starting`, `stopped`, or `running` plus default zone and panic mode. |
| Panic toggle | <IpcCommand command="firewall-panic-toggle" /> | Enable or disable panic mode (block all traffic). |

Open the tab with `helix-panel panel-toggle control-center firewall`.

## Printers {#printers}

Built-in Printers control talks to CUPS. There is no Helix config block; queues and jobs live in CUPS.

| Action | Command | Description |
|--------|---------|-------------|
| Status | <IpcCommand command="printers-status" /> | Print `not-installed`, `starting`, `stopped`, or `running` plus the default printer. |
| Start | <IpcCommand command="printers-start" /> | Start the CUPS printing service. |

Open the tab with `helix-panel panel-toggle control-center printers`.

## Privacy {#privacy}

Built-in Privacy control reads PipeWire capture links for microphone, camera, and screen share. Mute the microphone with `mic-mute`. Approximate location is `[location].auto_locate`. The startup ping is `[shell].telemetry_enabled`. Capture-name filters live under `[shell.privacy]` and affect the bar widget and OSD, not this status list.

| Action | Command | Description |
|--------|---------|-------------|
| Status | <IpcCommand command="privacy-status" /> | Print `idle` or `active` plus comma-separated app names per kind, plus `telemetry` and `location`. |

Open the tab with `helix-panel panel-toggle control-center privacy`.

## AI {#ai}

Built-in AI status reads AI CLIs on this machine (`claude`, `codex`, `gemini`, `qwen`, `ollama`, `local-ai`) plus running LocalAI and llama.cpp / vLLM servers. Settings live under [`[control_center.ai_usage]`](/helix/control-center/#ai).

| Action | Command | Description |
|--------|---------|-------------|
| Status | <IpcCommand command="ai-usage-status" /> | Print refreshing state, each visible CLI's plan and window percents (and used/max when known), LocalAI status with its models and capabilities and any install job, Ollama running/stopped and selected model, and llama.cpp / vLLM if they answered `/v1/models`. |
| Refresh | <IpcCommand command="ai-usage-refresh" /> | Refetch usage from local tools and APIs. |
| Start Ollama | <IpcCommand command="ai-usage-ollama-start" /> | Start the user systemd unit when present, otherwise `ollama serve`. Loads the selected model once the daemon is up. |
| Stop Ollama | <IpcCommand command="ai-usage-ollama-stop" /> | Stop the user systemd unit (and a serve process Helix started). |
| Set model | <IpcCommand command="ai-usage-ollama-model" /> | Persist `[control_center.ai_usage].ollama_model`, load it, and start Ollama if it is stopped. |
| Install model | <IpcCommand command="ai-usage-ollama-pull" /> | Download a model from the Ollama library (`POST /api/pull`). Starts the local daemon if it is stopped. |
| Cancel download | <IpcCommand command="ai-usage-ollama-cancel" /> | Cancel an in-progress `ollama pull`. |
| Remove model | <IpcCommand command="ai-usage-ollama-delete" /> | Remove an installed model (`DELETE /api/delete`). Starts the local daemon if it is stopped. |
| LocalAI endpoint | <IpcCommand command="ai-usage-localai-endpoint" /> | Print `url=… status=… model=… models=N` for desktop tools. The optional capability (`chat`, `vision`, `tools`, `thinking`, `transcript`, `tts`, `embeddings`, `image`, `video`, `sound`, `vad`, `rerank`, `detection`) picks the model: the pinned one when it qualifies, else a resident one, else the first match. Exits non-zero when LocalAI is not running. |
| Start LocalAI | <IpcCommand command="ai-usage-localai-start" /> | Start the `local-ai` user systemd unit when present, otherwise `local-ai run`. |
| Stop LocalAI | <IpcCommand command="ai-usage-localai-stop" /> | Stop the user unit (and a `local-ai run` process Helix started). |
| Set LocalAI model | <IpcCommand command="ai-usage-localai-model" /> | Persist `[control_center.ai_usage].localai_model`, the default model for chat requests. |
| Install LocalAI model | <IpcCommand command="ai-usage-localai-install" /> | Apply a gallery entry (`POST /models/apply`; a bare name means `gallery@NAME`) and follow the job until it lands. Queues until LocalAI is running. |
| Remove LocalAI model | <IpcCommand command="ai-usage-localai-delete" /> | Delete an installed model (`POST /models/delete/NAME`). |
| Open LocalAI | <IpcCommand command="ai-usage-localai-open" /> | Open the LocalAI web UI in the browser. |
| Desktop AI | <IpcCommand command="desktop-ai-status" /> | One-shot LocalAI tools. `desktop-ai-summarize`, `desktop-ai-translate`, `desktop-ai-rewrite`, and `desktop-ai-speak` use the clipboard. `desktop-ai-dictate` toggles the microphone. `desktop-ai-read PATH` and `desktop-ai-describe PATH` use a vision model. Results are copied to the clipboard. `desktop-ai-status` prints the in-flight state and the last result. |

Percents are utilization, not currency. Extra usage for Claude is a percent even when the OAuth payload includes credit fields. Codex prefers live `codex app-server` limits and falls back to the newest session `.jsonl`. Open the tab with `helix-panel panel-toggle control-center ai`.
