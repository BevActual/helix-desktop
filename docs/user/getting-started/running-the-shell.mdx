:::tip[Supported session]
Helix’s sole supported product surface is **Fedora + helix-niri**. See [Niri](/helix/compositor-settings/niri/) for compositor setup.
:::

### Autostart with helix-niri

This is the recommended method. The command is still `helix-shell` / `helix` depending on your install layout; the examples below use `helix`.

Add the following line to the end of your configuration file, typically `~/.config/niri/config.kdl`:

```ini
spawn-at-startup "helix"
```

If your session expects the startup command to return after the shell has initialized, run Helix Shell in daemon mode:

```bash
helix --daemon
```

Daemon mode returns after the shell has initialized. The optional polkit authentication agent starts asynchronously after the UI is up.

---

### Manual launch for debugging

```bash
helix
```

### Logs

Helix writes its main log to `$XDG_CACHE_HOME/helix/helix.log`. If
`XDG_CACHE_HOME` is unset, the fallback path is
`~/.cache/helix/helix.log`. The previous file is retained as
`helix.log.1` when the current log reaches 1 MiB.
